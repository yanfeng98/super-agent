# Agent Note: 启动体验成为原生客户端功能

Status: implemented

[English](2026-11-15-boot-animation-native-intro.md) | 中文

## 问题

第二个第三方插件 `dsh-startup-screen` 提出了另一种启动形态：不是一个片段，而是六幕可交互序列。它的代价比第一个更大——偏好是私有 JSON 文件、藏在自建 HTTP 端点之后；38 项设置没有翻译；1750 行命令式运行时代码没有类型与覆盖率方案；桌面端标题栏效果靠改 preload 探针的内联样式实现；录音素材取自第三方视频。

第三方插件 `dsh-boot-animation` 证明启动片头有真实需求，但把它留在仓库外要长期付四项代价：每次启动都要安装并靠强制刷新绕开缓存，偏好存在它自己的 JSON 文件里，界面文案没有翻译，测试断言的是它自己的构建产物而不是行为。它还带来两个不该被继承的缺陷：未监听媒体流的 error 事件可能终止 Host 进程；目录级的缓存签名会在文件被就地替换后继续公布过期的片段版本。

## 决策

两段都放在这一个包里，默认顺序是先播档案序列、再播片头片段。由同一个包承载，是因为它们共享同一次启动判定、同一个设置页、同一条启动记录和同一个浮层：拆成两个包就必须引入互斥规则，而唯一诚实的规则（「谁先注册谁播」）对用户不可见。`sequence` 决定播哪几段与顺序；`enabled`、`timing` 与按会话覆盖仍然作用于整段体验。

序列的偏好是与片段字段并列的扁平 `screen*` Config 字段。`src/screen.ts` 的一张表承载每个字段的默认值与取值范围，Host schema、设置页和运行时都按同一份事实归一化；设置页再由第二张表把每一行绑定到自己的字典文案。

档案序列由一个 `Frame` 对象描述「此刻屏幕上的一切」，由一条时间线函数驱动。跳过时用一个哨兵类拒绝所有待等待的计时，于是收尾只有一条路径，而不是每一步之后各写一个分支；声音引擎藏在一个可注入工厂之后，同一套代码既驱动真实媒体元素，也驱动测试里的假对象。录音台词放在 `assets/audio/` 下，Host 用与片源相同的 Range 与校验策略、从封闭名字集合送出；素材缺失时回落到系统合成音。

片头现在是一等包 `@deepseek-ai/dsh-client-ui-boot-animation`，由 `dsh-web-app` bundle 里的一行挂载。Desktop 运行的就是 Web profile，所以一行同时对两端生效；headless、ACP、SDK profile 永远不会加载它。默认开启：每次启动播一次、铺满窗口、品牌片头。

偏好是 Host 的 `Config` 字段（`enabled`、`timing`、`fit`、`random`、`selectedClip`），声明为 volatile，由本包自己的设置分区持有，并调用 `settings.configure({ auto: false })`。浏览器通过 `ctx.configForms` 读写，因此偏好留在 profile patch 里、换端口不丢，且不需要自建存储。按会话的状态——每次进入都播、以及该会话用哪段片头——放在 `boot_animation` 存储域里，通过可选的 `ctx.inject(['storageDomain'])` 打开；没有存储的组合仍然能播片头，只是少了这一页。

本包把插件里重叠的两个会话概念合并为一条记录：`{ replay, clipId }`。给会话指定片头与让它在每次进入时重播，本来就是同一会话的两个问题，一条记录即可回答，不必保留插件里"已固定但未覆盖"的状态。

内置片源就是 `assets/` 下的普通文件，由 Host 路由流式送出，不做 base64 内嵌：磁盘上 8.7 MB，而不是 JavaScript 模块里的 12 MB，安装路径上也没有解码步骤。媒体响应器写在本包内（单区间、ETag、版本钉住的 `immutable`），并显式处理流的 `error`、响应的 `close`，且在写状态行之前完成打开——唯一现成的第三方替代 `serve-static` 会为 120 行代码新增一个依赖。

## 影响

六幕保持「中文主字 + 英文等宽副标题」的双语美术，而不是随界面语言翻译的文案：这种配对本身就是设计。围绕它的界面文案——跳过、提示、身份卡标签、欢迎语——则是 8 种语言的字典文案。

桌面端标题栏现在是显式契约：任一阶段占用窗口期间，浏览器面在文档元素上设置 `data-dsh-splash`，`apps/desktop/src/preload-windows.ts` 在该属性存在时送出全透明的标题栏配色。上游插件改的是 preload 自己持有的探针 `<span>` 内联样式，那套实现一改就静默失效。

上游的若干行为刻意没有照搬，README 逐条列出：`screenSfx: 'synth'` 仍播放录音音效；`screenVoiceLang: 'both'` 实际念英语；背景模糊只留在浮层内部，不给应用节点加 `filter`（那会改变 `position: fixed` 的包含块）。

浮层 portal 到 `body`、`z-index: 900`，低于共享 Modal 的层级带：片头期间弹出的审批仍然在最上面。片段版本由每个文件的 size 与 mtime 计算，扫描签名覆盖每一个 entry，因此就地替换片段会让公布的版本失效，而不是永远钉住旧版本。

播放状态由浮层报告、而不是插件主体：元素首次触发 `playing` 时浮层调用 `markPlaying`，状态提示才从「正在加载视频…」变成「点击开启声音 · 全屏」。浮层自己调度并持有全部定时器、卸载时统一清理，因此超时提示不会在浮层消失后把下一段播放停掉；提示期间迟到的首帧也仍然正常播放。

`timing: 'entry'` 依赖会话绑定到达之后 `blank` 收敛；本包为此订阅了会话语义面，但宿主始终不收敛该标志时，这一次进入会跳过片头，而不是重复播放。

## 备选方案

- **直接移植第三方包**（纯 JavaScript、自建 JSON 偏好、未翻译文案、测试断言自己的产物）：否决，因为它过不了本仓库的类型、locale 与测试门禁，还会把两个缺陷一起带进来。
- **像插件那样把片源以 base64 嵌进产物**：否决，体积多 33%，安装路径上多一次解码。
- **按会话状态放进浏览器存储**：否决，本仓库的产品偏好由宿主承载；换端口或换 profile 就会丢。
- **媒体路由改用 `serve-static`**：否决，它仍然需要版本钉住的缓存与按片段的 URL，这个依赖几乎不承担工作。
- **保留"固定会话"与"会话片头"两个概念**：否决，一条记录就能回答两个问题。
- **把序列做成第二个包**：否决，两段共享启动判定、设置页与记录，第二个包只能靠一条对用户不可见的裁决规则。
- **逐行照搬上游命令式运行时**：否决，它过不了类型、本地化与逐文件覆盖率门禁，1750 行闭包里也没有给测试留缝。
- **保留上游的标题栏探针技巧**：否决，它改的是桌面端 preload 拥有的节点，依赖的是一处并不构成契约的实现细节。
