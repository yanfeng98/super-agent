# 00094 — 聊天里的行内评审、打回与合并收尾

- **日期**：2026-11-21
- **背景**：对照“主 Session 布置任务、worker 执行、完成后主 Session 问是否可以合并”的用法，评审和合并后的收尾仍有几处只有面板能做。本轮把其中五项补到聊天：按行/范围留备注、request changes、push 重试、暂停/恢复合并队列、清理已合并的 worktree。
- **范围**：`src/app/tools/main.ts`、`src/app/runtime.ts`、`tests/chat-tools.spec.ts`、`tests/model-surface.spec.ts`、`docs/002`、`docs/003`、`docs/005`、`docs/007`、`README.md`、`NATIVE.md`、`logs/`。

## 1. 评审动作

- `orchestrator_ticket_note` 新增 `file`、`line`、`end_line`：带 `file` 时走 `Engine.addNote` 记录一条锚定备注，而不是发消息；`line` 必须配 `file`，`end_line` 必须配 `line` 且不小于它，备注必须有 `text`。带 `review` 时仍把未发送的备注交给 worker 并恢复已结束的工单，所以“第 42 行有问题，发给他”一次调用完成。
- `orchestrator_ticket_review` 新增 `changes` 和 `note`：`changes: true` 记录 `changes-requested`，在下次批准前阻止合并；`approve` 和 `changes` 互斥，`note` 随决定写进评审记录，且只有批准/打回能带。
- 备注和打回都写 `via: chat`，与面板路径一致。

## 2. 合并后的收尾

- 新工具 `orchestrator_ticket_finish`：`push` 通过 `Runtime.pushTicket` 重试一次失败或从未执行的推送（合并或回退都适用），`cleanup` 通过 `Runtime.cleanupTicket` 删除已合并工单的 worktree 和分支；两者可同时用，记录 `via: chat` 并写入归档。
- `orchestrator_merge_queue` 新增 `paused`：暂停或恢复队列，恢复后按原顺序继续；与 `ticket_ids`、`cancel`、`retry` 互斥，避免一次调用既改队列状态又操作条目。目标分支检查失败暂停队列后，可以从聊天恢复，不必回面板。
- 运行时 `toolHost` 接上 `pushTicket`、`cleanupTicket`、`pauseMergeQueue`，三者都按聊天来源记录。

## 3. 模型面与工具数

- 工具数 24 → 25（新增 `orchestrator_ticket_finish`）。
- 模型面预算 65,500 → 67,500；实测 **67,058**（prompt 42,570 + tools 24,488）。增加的部分是新工具、备注锚点参数、评审决定参数和队列暂停参数。

## 5. 仍然存在的差距

- **分支保护**：worker 有 shell 权限，插件没有机制阻止它直接 push 目标分支；插件的 gate 只保护它自己执行的合并。
- **合并结果预检**：检查跑在工单分支上，合并后才在目标分支再跑一次；两个各自绿的改动合起来红，仍会先落地再报错/回退。
- **逐 commit 评审、suggestion、“已看过”标记**：只有整体 diff 加行备注。
- **提交信息**：squash/merge commit 的标题和正文自动生成，不能改。
- **CI 失败通知**：followed PR 的 CI 失败仍只进面板通知和 webhook，不进聊天。
- **面板-only 动作**：搜索、关联工单、改名、标签、编辑请求文本、单独 rebase 仍在面板。
- **过期批准**：批准绑定当时的 head，新 commit 后不会自动失效（`requireReview` 关闭时）。
