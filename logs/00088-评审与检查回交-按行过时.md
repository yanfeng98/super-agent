# 00088 — 评审与检查回交、按行过时

- **日期**：2026-11-20
- **背景**：上一轮列出的三个问题：主会话看不到评审备注和检查结果；评审意见和检查失败只能从面板交回，工单结束后 `orchestrator_ticket_note` 直接报 `ticketEnded`；备注的“过时”按整个 head 判断，发送后仍挡合并、只能逐条解决。
- **范围**：`src/core/model.ts`、`src/core/tickets.ts`、`src/core/engine.ts`、`src/app/runtime.ts`、`src/app/review.ts`、`src/app/cards.ts`、`src/app/resources.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/app/tools/main.ts`、`src/app/views/tickets.ts`、`src/client/ticket.tsx`、`src/client/locales.ts`、`tests/`、`docs/001`–`007`、`README.md`、`NATIVE.md`、`logs/`。

## 1. 聊天里能看到评审和检查

- `ticketDetails` 增加：
  - `review`：分支、base、head、提交数、改动文件数、未提交文件数、`git diff --shortstat`，以及捕获失败时的原因；
  - `reviewed`：评审决定、时间、评审人、备注；
  - `notes`：总数、未解决数、最近 10 条（文件、行/区间、文本预览、是否已解决/过时/已交回、回复数），并指向 `ticket/<id>/notes`；
  - `checks`：最近一次检查的完整记录（含输出，检查本身最多保留 4000 字符）、`checkRuns` 的逐项摘要、`targetCheck` 和 `mergeError`。
- 新增只读资源 `ticket/<id>/notes`，按最新在前返回每条备注的全文、状态和回复；只对主会话开放。
- `ticket/<id>/diff` 的正文前增加文件统计头：文件数、总增删行数，以及每个文件的状态和 `+N -M`，主会话不读完整 patch 也能说清改了什么。
- 备注的 `notes` 只给主会话；worker 仍读不到面板里的草稿备注。

## 2. 评审意见和检查失败可以交回

- `orchestrator_ticket_note` 的 `text` 改为可选，新增 `review`、`check` 两个布尔参数；三者至少一个。
  - `review: true`：把未解决且未交回的备注合成一条 note；
  - `check: true`：把当前结束的失败检查的命令和输出合成一条 note；
  - `text`：照常发送一段话。
- `Runtime.handbackTicket` 统一处理：
  - 工单还开着：`engine.note` 追加 Input，由正常的投递路径送给 worker；
  - 工单已结束：`engine.resumeWithNote` 用这条 note 恢复工单；结束于人的停止、已合并/丢弃/清理、或处理暂停时给出明确报错，不改工单；
  - 交回成功后把相关备注标成 `sent`，同一条备注不会重复发送；回复或重新打开会清掉 `sent`，下次可再交回。
- `POST tickets/:id/handback` 与面板共用同一条路径；面板的 **把备注发给执行器** 不再只对本地工单显示，**让执行器修检查** 在检查失败时出现。
- 面板新增 **全部解决**，`POST tickets/:id/notes/resolve` 一次解决或重新打开所有备注；备注列表显示 **已交回**。

## 3. 备注只在自己的行变化时过时

- `TicketNote` 增加 `sent`、`checkedHead`、`stale`；`noteOutdated` 统一判断：
  - 有 `stale` → 过时；
  - 已按当前 head 检查过 → 不过时；
  - 没有检查记录（旧记录）→ 退回“提交不同即过时”的旧行为。
- `staleNoteIds` 对每条备注的提交到当前 head 做一次 `git diff --unified=0 -M`，按文件解析旧行区间：
  - 备注的行/区间与改动区间相交 → 过时；
  - 文件级备注只在有内容行变化时过时，纯 mode 变化不算；
  - 新增、删除、重命名、二进制文件按整文件处理；
  - git 失败时该备注保持未检查，页面走旧的回退判断。
- 工单结束、合并前重新捕获、rebase 时都会重新计算并写回 `checkedHead`/`stale`；分支只是前进、备注自己的行没变时不再标过时。

## 7. 仍然存在的差距

- 堆叠工单：`blockedBy` 只挡合并、不挡开工，新工单的工作树仍从目标分支创建，不能基于另一个未合并工单的分支；prepare 命令也拿不到 base ref。
- 合并目标只能是当前检出的分支；队列串行，慢检查会阻塞后面的条目；目标检查失败只暂停并通知，不自动回退。
- 评审没有 suggested change；`outdated` 仍是按行区间判断，不跟踪行在 rebase 后的新位置。
- 单人部署，没有按人分配评审人、多人批准或 CODEOWNERS。
