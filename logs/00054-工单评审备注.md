# 00054 — 按文件/行评审备注

- **日期**：2026-11-18
- **背景**：对比 GitHub 清单第 8 项：本地工单没有行级评审评论，反馈只能整段 follow-up。本日志记录按文件/行锚定的评审备注及其一次发送。
- **范围**：`apps/web/native/dsh-superagent`（`src/core/*`、`src/app/runtime.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/app/views/tickets.ts`、`src/client/ticket.tsx`、`src/client/locales.ts`、`docs/`、`tests/`）。

## 1. 改动

| 项 | 内容 |
|---|---|
| 数据 | `Ticket.notes: TicketNote[]`（`id`、`file`、可选 `line`、`text`、`at`） |
| 领域 | `Tickets.addNote` / `removeNote`：拒绝空文件或空内容、拒绝未知备注；`Engine` 暴露同名方法 |
| API | `POST tickets/:id/notes`（文件名 ≤500、行号 1–1,000,000 可选、内容 ≤2000）与 `POST tickets/:id/notes/:noteId/remove`，返回最新 `notes` |
| 面板 | **变更** 区块列出备注（`文件:行` + 内容 + 时间），可添加与删除；本地工单可点 **把备注发给执行器**，把全部备注拼成一条 follow-up 发到本地 Thread，从而恢复已结束工单并让执行器读到 |
| 文案 | 新增 `noteFilePlaceholder`、`noteLinePlaceholder`、`noteTextPlaceholder`、`noteAdd`、`noteSend`、`noteMessage` 及 `emptyNote`、`unknownNote` 错误文案 |

备注不是 Trigger，不参与授权，也不影响合并；发送后才成为线程里的正式消息。

## 2. 验证

- `tests/local.spec.ts`：添加/删除备注、空内容拒绝、未知备注拒绝。
- `tests/views.spec.ts`：详情返回备注列表。
- `tests/http.spec.ts`：两条备注路由。
- `tests/panel-execution.spec.tsx`：页面显示 `src/a.ts:12`，添加备注发出正确 POST，发送按钮把备注拼成一条 `local/followups` 消息。
- 全量包测试 64 文件、1268 用例通过；`tsc --noEmit` 通过。

## 3. 仍按设计不做

- 标签颜色/描述、里程碑、优先级、截止日期：单人使用自由标签已够用。
- 邮件/摘要通知：Webhook 可接入任意通道。
- 镜像已有 GitHub Issue 列表：GitHub Source 开启 `observeIssues` 时会把新 Issue 作为触发接收，不提供待办列表镜像。
