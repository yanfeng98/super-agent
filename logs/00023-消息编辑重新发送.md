# 00023 — 用户消息编辑并重新发送

- **日期**：2026-11-16
- **背景**：用户反馈消息发错后没有入口修改并重发。Session 日志只追加、不重写，因此不能在原会话内替换一条已入档消息；本功能把「修改并重发」实现为从目标消息之前分叉，再把编辑后的文本发送到新分支，原会话及其后消息保持不变。
- **范围**：`packages/client/ui-chat`（消息操作、编辑弹窗、分支发送编排、权限判定、8 语言文案、测试、双语 README）、`apps/web/tests/message-actions.e2e.ts`、`snapshots/web/**` 金标、本日志。

## 2. 行为

| 场景 | 行为 |
|---|---|
| 编辑普通文本消息 | 弹窗预填原文；确认后从该消息所在 Turn 之前 fork，子会话继承此前全部内容，标题递增，编辑文本作为新提示词发送。 |
| 编辑首条消息 | 没有可继承前缀，在源 Workspace 按源 `cwd` 与 Agent preset 新建 Session 后发送。 |
| 目标 Turn 正在运行 | 先取消该 Turn，再分叉；取消失败则中止编辑并提示。 |
| 附件/非文本/未加载 Turn 起点 | 按钮禁用并解释原因；不会发送。 |
| 子智能体会话/只读或无 `session/prompt`、`session/fork`、`session/cancel` 权限 | 不提供可用的编辑操作；Host 仍为最终权威。 |
| 提示词被接受 | 子会话显示，编辑文本正常入档；原会话不变。 |
| 提示词拒绝/抛出 | 子会话仍打开，编辑文本恢复到输入框；原错误被重抛给弹窗或子会话的 prompt error 面。 |

- 原 Session 不写入替代消息，也不删除后续 Turn；编辑后的历史只存在于新分支。
- 不改动服务端、wire、Session 格式或模型请求组装；仍通过现有 `session.fork` / `session.create` / `session.prompt`。
- 没有新增产品埋点；与本地 UI 交互一致。

## 4. 设计取舍

- **分支而不是原地改写**：Session 日志不可变，原地替换会破坏审计、fork 语义和已有投影；代价是编辑后产生新会话，后续消息留在原会话。
- **首条消息新建 Session**：在 `turn.start.seq === 0` 时 fork 会产生一个空的合成 Turn，污染导航；新建会话语义等价且干净。
- **目标 Turn 运行中先取消**：避免原分支继续消耗 token；若取消权限缺失则直接不提供操作，比静默分叉更明确。
- **文本-only**：现有附件以 Host 上传回执和 Session 级引用存在，无法安全搬进新分支；保持该限制并显式提示，不做静默丢附件。
- **弹窗而非 composer**：不打断当前草稿，也不把「编辑历史」伪装成普通新消息；弹窗能明确展示「将新建分支」。
- **失败恢复优先**：子会话先打开再恢复草稿，用户不会失去已编辑文本；代价是失败时源视图可能已切换，错误由子会话的 prompt error 面承接。
- **可选 `workspaces` / `conversation`**：保持既有 Chat 组合可加载；缺少它们时仍可发送，只是首条消息无法定位 Workspace、失败时无法恢复草稿。正常 Web 组合两者都存在。
- **不新增 Agent Note**：按既有本地 UI 交互先例（如 `00011-Composer按文件夹的输入历史.md`），交互实现与取舍记入包 README 与本日志；未新增独立决策笔记。

## 6. 已知限制与后续

- 编辑仅支持纯文本；附件、图片、未知内容块不参与编辑。
- 编辑较早消息会把其后的消息留在原会话，新分支不继承它们；弹窗与 README 已明确说明。
- 首条消息编辑新建的 Session 使用源 Session 的 `cwd` 与 Agent preset，但模型选择沿用 Host 默认（`sessions.create` 当前没有携带源模型选择的入口）。
- 目标 Turn 运行中取消会终止原分支当前生成；源会话中排队的消息不随分支迁移。
- 子智能体会话不提供编辑；如未来需要，应单独设计子会话分支语义，而不是复用普通会话的入口。
- 全仓 `build` 当前被并行中的 `ui-boot-animation` 改动阻塞；该批改动不属于本功能，未在本日志中修改或回滚。
