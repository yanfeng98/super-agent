## 4. 设计取舍

- **只在 dsh 层移除**：不修改 `node_modules/@earendil-works/pi-ai`，避免上游同步冲突与 `verify-provider-data` 漂移。`WITHHELD_PROVIDERS` 与 `resolveProfiles()` 是仅有的两个控制点。
- **删除 Azure 专属测试而不是跳过**：这些用例验证部署名映射、混合协议与目录外模型的协议推断；路由不再提供后行为不可达，保留会误导读者。
- **`AZURE_OPENAI_*` 生成元数据保留**：`provider-data.generated.ts` 必须完整覆盖已安装 pi-ai 目录，`verify-provider-data` 会校验；它描述的是上游元数据，不是可售路由。
