# 00134 — 主会话被删除后自动重建

- **日期**：2026-11-26
- **背景**：用户在 DSH Web 界面删除 dsh-superagent 的主会话后，飞书消息不再有响应，主会话也再打不开。superagent 把主会话 ID 持久化在 KV 中，启动时只确保一次；运行期投递时 `resolveAgent` 持续返回 `session/not-found`，持久化的 relay 与 assessment effect 一直重试却永远送不到。
- **原因**：主会话的解析没有“缺失即重建”的路径。dsh-im 在同场景下由 `askInWorkspaceSession` 在收到消息时新建会话，superagent 的 `Sessions.prompt` 与 `Sessions.inject` 直接抛错或静默跳过。

## 1. 变更

| 位置 | 变更 |
|---|---|
| `src/app/sessions.ts` | 新增 `ensureMaster()`：按记录的 ID、工作目录和 router preset 重建主会话，并发调用共享一次在途创建；`masterAgent()` 在 `session/not-found` 时触发重建，并对已存在的会话补做幂等装饰。`prompt` 走重建路径；`inject` 前三次失败用 `Later` 重排而不丢队列行，持续失败转为普通错误以触发健康告警。`ensure` 在 DSH 因删除中的 ID 而铸造新会话时清理该空白会话并延迟重试 |
| `src/app/runtime.ts` | 把主会话的工作目录与标题传给 `Sessions`；恢复成功后通过 `onMasterReady` 重放持久化的侧栏 Workspace 分组 |
| `tests/runtime.spec.ts` | 覆盖删除后飞书消息重建、并发消息只创建一次、notice 路径重建与注入、Workspace 分组回填、铸造会话清理、持续不可用时健康从 ready 变 error |
| `docs/001-domain.md`、`README.md`、`docs/007-architecture.md`、`NATIVE.md` | 记录用户可见行为、实现语义与 vendored 副本的本地改动 |

## 2. 判断

- 重建沿用原会话 ID 与 `dsh-superagent-router` preset，但新会话不带旧会话的历史上下文；工单与执行器会话不受影响。
- notice 不能在无法解析主会话时被当作已投递而静默删除队列行，也不能让一个永久不可恢复的主会话把健康状态一直显示成正常；短重试后转为可报告的错误是两者的折中。
- DSH 在删除围栏内对同名 `create` 会铸造随机 ID，因此恢复需要检查 `create` 返回值并清理刚生成的空白会话，避免每次重试留下孤儿。

## 4. 后续说明

- 删除后由下一条飞书消息或排队的 notice 触发重建；如果用户希望立即恢复，可在面板发一条本地请求或等待队列中的 notice 到期。
- 归档（archive）不是删除：归档会话仍可解析，不触发本重建路径。
