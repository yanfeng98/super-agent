## 2. 行为

- **菜单**：`内置 · mattpocock/skills` 组由 27 项增到 32 项，新增的 5 项都带「仅用户」标记，只能由用户点名。
- **模型请求不变**：模型可调用的仍是原来 11 个，会话技能目录条目数量不变，因此请求侧 token 与 KV 缓存不受影响。
- **来源与稳定性**：新增的 5 个来自上游 Beta 桶，上游声明可能无预告地改名或删除；重新同步时可能移除其中之一，这一点写进了包 README 的已知限制。
- **覆盖关系**：仍按层覆盖。用户或项目里放一份无前缀的同名技能会与 `eng-…` 并存，只有同名 `eng-…` 才覆盖随包版本。

既有问题（与本次改动无关）与处理：

- `pnpm run test:snapshot` 在 `snapshots/sdk/*` 与部分 `snapshots/session/headless.snapshot.ts` 场景失败，差异是录制里缺少 11 个 `eng-*` 目录条目（期望只有 office 4 个）。把随包提供方回退到上一个提交里的 27 个技能后，同一场景仍以相同差异失败，重新构建产物后也失败，因此不是本次改动引入；原因是随包工程技能进入 base 之后，这批 fixture 记录时还没包含它们。
- 处理：用 `pnpm run test:snapshot:refresh` 重放整套快照，63 个录制文件补齐 11 个 `eng-*` 目录条目（只保留目录相关的行，纯时间戳变动已还原）。失败用例从 45 个降到 6 个。
- 其中 4 个 PTC 场景（`ptc-node-workspace`、`ptc-persistent`、`ptc-persistent-scoped`、`ptc-reset`）是 fixture 自相矛盾：录制里的 `run_code` 返回 `sandbox-unavailable`（本机既没有 bubblewrap 也没有可用的 Landlock），所以最终工作区必然为空，而 `workspace.expected/` 仍留着上一次成功录制的产物文件。把期望改成 `.empty` 标记后 4 个场景通过，快照套件从 45 个失败降到 2 个。
- `worktree` 的根因是本机 Git 2.34 不支持 `git worktree list --porcelain -z`（2.36 才加入）：git 调用追踪显示插件扫描以 129 退出，`enter_worktree` 因此没有真正建出 `doomed`，随后的删除命令在 `/` 里以 128 失败。快照套件为此加了 Git 版本能力门禁：低于 2.36 时跳过 `worktree` 场景（与 `pwsh` 场景按探测结果跳过的做法一致），现代 Git 上仍照常执行。
- `ptc-workspace-context` 的根因是本机 `/tmp/.git`（一个空目录残留）：`findProjectRoot` 据此把项目根解析成 `/tmp`，于是工作区指令的前缀被渲染成 `<随机目录名>/AGENTS.md`，`scope` 与 `baselineIdentity.projectRoot` 也跟着带上了它。同一处残留也是 `skill-filesystem` 的 fallback-root 用例一直失败的原因。删掉这个空目录后，实际输出恢复为 `Instructions from: AGENTS.md`、`nested/AGENTS.md`，把录制里被污染的对应行改成干净形态（含 `scope` 的 NUL 分隔符与空的 `projectRoot`）后场景通过。
- 最终快照状态：275 通过 / 0 失败 / 3 跳过（2 个 `pwsh` 场景因本机没有 `pwsh`，外加 `worktree` 的 Git 版本跳过）。快照 fixture 的逐项修复过程与 `worktree` 的 Git 版本要求见[日志 00117](00117-快照fixture修复与worktree的Git版本要求.md)。
