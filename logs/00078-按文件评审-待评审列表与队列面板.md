# 00078 — 按文件看 diff、待评审列表、评审人与队列面板

- **日期**：2026-11-19
- **背景**：00077 之后剩下的差距偏向评审体验：diff 只有一整段、没有“待评审”视图、评审记录没有评审人、合并队列只在工单页露出一个位次。这轮补这三块。
- **范围**：`src/app/review.ts`、`src/app/runtime.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/app/views/tickets.ts`、`src/app/merge-queue.ts`、`src/core/model.ts`、`src/core/tickets.ts`、`src/core/engine.ts`、`src/sources/local.ts`、`src/kv.ts`、`src/client/ticket.tsx`、`src/client/execution.tsx`、`src/client/locales.ts`、`docs/001`–`007`、`README.md`、`NATIVE.md`、`tests/`。

## 1. 按文件看 diff

- `src/app/review.ts` 新增 `parseDiff`：按 `diff --git` 切块，识别新增/删除/重命名/修改，统计增删行数，保留整段 patch；`workspaceDiff` 和 `ticketDiff` 的返回值增加 `files`（`GET tickets/<id>/diff` 同样多一个 `files`）。
- 面板的 **View diff** 改为文件列表：每个文件显示路径、状态、`+N −M`，点路径展开这一段 patch，**已查看** 是浏览器本地记录（按工单 + 提交存 localStorage），换提交自动重置；文件多时顶部显示文件数。
- 空 diff、非 git 工作区、超大截断的提示保持原样。

## 2. 待评审列表

- `TICKET_FILTERS` 增加 `review`：已结束、未合并/丢弃/清理、且没有批准的工单；批准后从列表消失，新提交清掉批准后重新出现。
- 面板 Tickets 页多一个 **待评审** 过滤片，并带一句说明。

## 3. 评审人

- `TicketReviewRound.by`：评审时由 runtime 填入部署的操作者标签（本地 Source 的 `operator`），归档的评审节也用同一个值。
- 工单历史里每条评审显示“评审人：{name}”。单人部署下它固定是 operator，将来接入真实用户身份即可填人名。

## 4. 队列上页面

- 队列新增暂停：`KV.runtime.mergeQueuePaused`，`Runtime.pauseMergeQueue`，pass 的排空逻辑和单次 `runMergeQueue` 都会尊重它（暂停时保持顺序、不动任何一条）。
- **目标分支检查失败时自动暂停队列**（队列里有下一条时），通知文字里说明“merge queue is paused”，避免下一条合进一个红的分支。
- 面板 Execution 页新增 **合并队列** 区块（`GET merge-queue`）：显示顺序、编号、标题、策略、暂停状态，提供 **暂停/继续队列** 和每条 **移出队列**；队列为空且未暂停时不显示。
- `POST merge-queue/pause` 管理 API。

## 5. 测试

- `tests/review.spec.ts`：`parseDiff` 覆盖修改/新增/删除/重命名、空 diff 和二进制文件回退。
- `tests/views.spec.ts`：待评审列表只列未批准的已结束工单，批准消失、清掉批准后回来。
- `tests/core-engine.spec.ts`：评审记录带上 `by`。
- `tests/merge.spec.ts`：目标检查失败暂停队列、下一条等待、恢复后继续。
- `tests/panel-execution.spec.tsx`：diff 文件列表与展开、**已查看** 写入 localStorage、评审历史显示评审人、队列区块与暂停/移出操作。

## 7. 仍然存在的差距

- 没有按人分配评审人、多人批准、CODEOWNERS；`by` 目前只有一个取值。
- 已查看标记存在浏览器里，不进工单记录，换浏览器不同步。
- 队列是串行执行，慢检查会拖住后面的条目；没有“按最新目标重排后重试”。
- 合并后目标检查失败只暂停队列并通知，不自动回退。
