# 00063 — 同步上游 0.2.2-rc.5

- **日期**：2026-11-19
- **背景**：上游 `deepseek-harness` 在上次同步点（rc.4 发布线的 `master`，2026-11-17）之后前进了 238 个提交（139 个非 merge），并打出 `dsh-v0.2.2-rc.5` 标签；`master` 于 2026-11-18 完成 rc.5 回灌。用户要求先把本仓库与源仓库同步，再继续改造。
- **判断依据**：本仓库改动最密集的 `packages/client/ui-conversation`、`ui-chat`、`ui-settings-models`、`api/session-controller` 与上游这一轮重叠只有 34 个文件，试合并实测 5 个冲突（全部是文档与翻译哈希记录），同步成本低；而 rc.5 改到了沙箱边界、客户端 Config 下发与 SQLite 提交路径，继续叠加改造后再同步会更贵。
- **范围**：整仓；重点在 `packages/sandbox/sandbox-policy`、`packages/client/connection`、`packages/session/session-persistence-sqlite`、`packages/connector/*`、`packages/experimental/client-ui-forge`、`docs/`、`logs/`。

## 1. 上游带来的变化

| 方向 | 内容 |
|---|---|
| 新包 | `connector/linear`、`connector/notion`（OAuth 连接账号、连接器面板、快照与 e2e） |
| Forge | 代码评审页（列表、评论引用进对话、骨架屏、限流失败升级指南）、评审仓库菜单修复、评审会话释放 |

| Web 与桌面 | 侧栏面板行尾部内容（trailing content）、面板行标题跑马灯、持久化终端的控制项恢复、桌面安装器拖拽完成提示、历史段去重与开发状态目录隔离 |
| CUA | macOS/Windows 窗口级鼠标按键保持与按平台准入；审批后按原生清理顺序等待 |
| 工具与检索 | `repeat-tool-reminder` 排除嵌套调用；`web_search` 的默认模型改为 DeepSeek 检索模型（升级指南） |
| 工程 | 版本全面升到 `0.2.2-rc.5`；`tsconfig`、`pnpm-lock.yaml`、目录生成脚本与 `dependency-catalog` 同步 |
| 升级指南 | 4 篇：`client-hmr-plugin-events-stream`（rc.3）、`forge-rate-limited-failure`、`web-search-deepseek-model-default`、`workspace-write-boundary-follows-root`（rc.4） |

## 2. 合并与冲突

同步分支 `sync/rc5` 从 `main` 拉出，`git merge upstream/master` 只产生 5 个冲突，全部是文档：

| 文件 | 处理 |
|---|---|
| `docs/config-catalog.md`、`docs/config-catalog.zh.md` | 生成型：取上游版本，再跑 `gen-config-catalog` 重新生成本仓库的条目（含 `ui-boot-animation` 等） |
| `docs/capability-seams.i18n.yaml`、`packages/client/ui-conversation/README.i18n.yaml`、`packages/client/ui-settings-models/README.i18n.yaml` | 哈希记录：两侧键集完全相同，取上游后跑 `verify-translation-pairing --write` 按合并后的正文重录 |

合并提交第一次被 pre-commit 钩子拦下：`translation pairing (staged records)` 校验的是索引字节，重录后的哈希必须先 `git add` 再提交。

两边都改过的另外 29 个文件是逐段相加的改动，自动合并后逐项复核：`packages/bundle/web-app/package.json`（本仓库多挂 6 行、上游新增依赖）、`tsconfig.base.json`/`tsconfig.host.json`/`apps/web/tsconfig.json`（本项目新增路径与上游新增 e2e）、`scripts/gen-cordis-catalog.ts`/`gen-doc-graphs.ts`（本项目补的服务与链接、上游补的 Forge 类型）、`packages/client/ui-chat/src/client/apply.ts`（本项目的 edit-resend 与上游的 session directory 并存）、`packages/client/ui-settings-models/src/client/index.ts`（本项目的登录入口与上游的 Config 下发并存）。上游未触及 `apps/web/native/`（IM 与 Superagent，978 个文件）与 `packages/im` 对应渠道裁剪，因此这两块零冲突。

## 5. 结果

- 本仓库与上游 `0.2.2-rc.5` 对齐，同时保留全部本仓库能力：11 个 pi-ai 路由 / 175 个模型、IM 原生渠道、Superagent 工单系统（含主会话建单与回答）、永久删除会话、编辑重发、输入历史、启动片头、Markdown 表格收列。
- 行为没有变化：`workspace-write` 边界变化只影响在链接工作树里以 `workspace-write` 运行的 Session，本仓库的 Superagent 工单 Session 用 `danger-full-access`，普通 Web 会话仍在仓库根目录工作。
- 新增能力随上游进入：Linear 与 Notion 连接器、Forge 代码评审页、侧栏面板行尾部内容、SQLite 组提交。
