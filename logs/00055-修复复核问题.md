# 00055 — 修复复核发现的问题

- **日期**：2026-11-18
- **背景**：对 00051–00054 的改动逐项复核，发现变基、检查门、清理、归档与批量操作中的若干正确性问题，本日志记录发现与修复。
- **范围**：`apps/web/native/dsh-superagent`（`src/app/review.ts`、`src/app/check.ts`、`src/app/runtime.ts`、`src/app/views/*`、`src/core/tickets.ts`、`src/sources/local.ts`、`src/client/*`、`tests/`）。

## 1. 发现与修复

| 问题 | 影响 | 修复 |
|---|---|---|
| 变基后仍用启动时的 `execution.base` 采集 review 与 diff | 工单页把目标分支新提交也算成工单改动 | `rebaseWorkspace` 返回目标提交作为新 base；`rebaseTicket` 更新 `execution.base` 后再采集，review 只含工单自己的提交（新增真实 git 断言） |
| 变基不清理旧检查结果 | 变基引入上游代码后，旧的通过结果仍可放行合并 | 变基时删除 `checks`；合并门要求检查时间不早于本次结束时间 |
| 结束时的检查可能写进已恢复的工单 | 恢复后工单显示上一次结束的检查 | 检查写库前再次确认工单仍以同一时间结束 |
| 重启对账写关闭段时丢掉检查结果 | 崩溃恢复后的归档缺少检查状态 | 对账把当前结束的检查传给 `closeArchive` |
| 重启对账漏记清理与变基 | 崩溃后归档缺少 Cleaned/Rebased 段 | 对账补 `recordCleanup`、`recordRebase` |
| 已合并或已清理的工单仍显示/执行「运行检查」 | 清理后目录不存在，报错误导 | 视图隐藏、运行时拒绝 |
| 已合并的工单仍可重开 | 重开后 `merged` 残留，清理会删掉新 worktree 与未合并分支 | 重开拒绝已合并工单（`ticketMerged`），页面不显示 Reopen |
| 清理在移除 worktree 后才检查分支是否已合并 | 分支未合并时先丢 worktree、再报错 | 先做 `merge-base --is-ancestor` 包含检查，再移除 worktree |
| 批量合并多张工单在本地几乎必然失败 | 第一次快进后其余分支落后于新目标 | 批量操作改为「停止开放工单」+「清理已合并工单」；合并保持逐单确认 |
| 请求全文藏在输入折叠区，已送达后要展开才看得到 | 与「工单页显示请求全文」的意图不符 | 新增「原始请求」区块置于回复之前，输入行只保留预览，避免重复 |
| 未知 `is:` 值被吞掉前缀 | `is:merged` 变成搜索 `merged` | 保留原 token 作为普通文字 |

另外补了工单操作历史的视图测试（此前只有面板测试）、请求全文在面板渲染的测试，并给归档的 Rebased 段加了幂等测试。

## 2. 验证

- `tests/review.spec.ts`：变基返回新 base、变基后 review 仅含工单提交、未合并分支拒绝清理。
- `tests/check.spec.ts`：检查时间早于本次结束时仍拒绝合并。
- `tests/local.spec.ts`：已合并工单拒绝重开、Rebased 段幂等。
- `tests/views.spec.ts`：操作历史顺序（含变基）、合并后不显示 Reopen。
- `tests/panel-execution.spec.tsx`：批量清理替代批量合并。
- 全量包测试 64 文件、1271 用例通过；`tsc --noEmit` 通过。

## 3. 未改

- 批量合并没有做成自动 rebase + 合并：检查门与冲突处理会让它变成隐式长任务，风险高于收益；合并仍逐单进行。
- 0.2.2 时代旧工单没有 review base 的情况维持原样，不做数据迁移。
