# 00086 — 推送闭环与 diff 行内评论

- **日期**：2026-11-20
- **背景**：上一轮列出的两个剩余问题：面板合并/回退之后没有推送入口（回退还会删掉 `merged`，`pushTicket` 也拒绝）；评审只能手填文件名和行号，不能点 diff 行评论。
- **范围**：`src/core/model.ts`、`src/app/runtime.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/app/views/tickets.ts`、`src/app/tools/main.ts`、`src/client/ticket.tsx`、`src/client/diff.ts`（新）、`src/client/client.css`、`src/client/locales.ts`、`tests/`、`docs/002`、`docs/005`、`docs/006`、`docs/007`、`NATIVE.md`、`logs/`。

## 1. 推送闭环

- `TicketRevert` 增加 `root` 和 `push`：回退时记下仓库位置，推送结果记在回退上。
- `Runtime.revertTicket(id, origin, { push })`：回退后可以一并推送；推送失败不回滚回退，返回 `pushError`，记录 `reverted.push`，并留一条 `push` 通知。
- `Runtime.pushTicket` 现在接受“已合并”或“已回退”的工单：已回退时用 `reverted.target` 和 `reverted.root`，结果写回 `reverted.push`。错误文案改为 “Only a merged or reverted ticket can be pushed”。
- 面板：
  - 合并控件新增“合并后推送”复选框，`POST tickets/:id/merge` 接受 `{ push }`。
  - 合并或回退只要还没有成功推送过，就显示 **推送**；上一次推送失败时显示 **重试推送**。
  - 回退的推送结果显示在页面上，历史里也带推送结果。
- chat：`orchestrator_ticket_revert` 增加 `push` 参数；同时修正了它此前把 `via` 记成 `panel` 的问题，现在记录 `chat`。
- `POST tickets/:id/revert` 接受 `{ push }`；`readBody` 在请求没有 body 时返回 `undefined`，所以旧的不带 body 的调用仍然有效，畸形 JSON 仍然报错。

## 2. diff 行内评论

- 新增 `src/client/diff.ts` 的 `patchLines`：把 `diff --git` 块解析成带新旧行号的行，`@@` 头、文件元信息和 `\ No newline` 不占行号。
- 每个“改动后的文件里存在的行”（上下文行和新增行）悬停出现“＋”，点击后把文件名和行号填进备注表单并聚焦输入框；删除行没有改动后的行号，因此不提供行内评论（模型里备注没有 old/new 侧别，避免把评论锚到错误的行）。
- 已有备注渲染在它锚定的那一行下面，已解决备注用弱化样式；备注列表和操作保持不变。
- 超过 2000 行的 patch 退回整块 `<pre>`，避免一次渲染上千个行节点。
- 样式沿用现有 token：新增/删除行用 `color-mix` 叠在 `--dsw-alias-bg-l2` 上，行号列固定宽度，评论按钮在横向滚动时贴住右侧；触屏设备上按钮常显。

## 5. 复核修复

- `patchLines` 原来把任何以 `---` / `+++` 开头的行都当成文件头：hunk 里删除内容为 `--` 的行、或新增内容为 `++` 的行，会被误判成元信息，行号和评论锚点都会错。现在文件头只在第一个 `@@` 之前识别，hunk 内一律按内容行处理，并加了用例（删除 `--`、新增 `++`）。
- 推送结果原来只按“当前有没有 `merged`/`reverted`”写回：如果推送期间另一条合并或回退先落库，结果可能记到新记录上。`savePush` 现在带上目标（合并的时间戳或回退的提交），记录仍匹配才写回。
- 补了一条真实 git 用例：合并 → 回退 → `pushWorkspace`，断言远端分支等于本地 HEAD、被回退的文件在本地消失。
- `pushTicket` 把“工单不是已合并/已回退”和“合并或回退没记下仓库”拆成两条报错，旧记录缺仓库时仍给出可操作的提示；面板测试夹具只允许 API 类型里有 `body` 的路由声明 body。
