# 00126 — 飞书主人改为一次采纳，删除后永久生效

- **日期**：2026-11-23
- **背景**：00124 让飞书机器人的主人在每次同步时补进 superagent 的名单。用的人随后提出：从名单里删掉的主人又被自动加回，删除应当永久生效。
- **结论**：主人的采纳从「每次同步都补」改为「每个主人只采纳一次」。策略里新增 `adoptedOwners` 记录已经采纳过的主人 open_id：已采纳又被删掉的主人不再自动加回；机器人后来新增的主人仍会在下一次同步时加入。设置了同步来源群时名单由群成员加主人共同决定，群模式保持每次合并（名单由外部花名册决定，删除本来就不持久）。

| 位置 | 变更 |

## 2. 原因与判断

- **为什么不是「名单为空时播种」**：清空名单会让下一次同步把主人全部加回，「删了就永久生效」在最后一条上也站不住。改成记录「已采纳过谁」，删除才真正持久。
- **为什么后来新增的主人仍自动采纳**：打开「交给 Superagent」的人期望 dsh-im 里改主人就够，不必再来 superagent 配第二份。`adoptedOwners` 只拦「采纳过又被删」的 id，不拦新主人。
- **为什么群模式保持每次合并**：设置了同步来源群时，名单本来由群花名册重建，手动删除本来就会被下一次同步覆盖——「删除永久」只对无群的手动名单有意义。群模式下主人始终与群成员并列，保证不在该群的主人仍能私聊发起工作。
- **为什么记录放在策略片段里**：与它守护的名单同存同灭，随策略版本一起保存（`Settings.sync` 只在片段变化时记新版本），面板保存整段策略时一并保留；不引入第二份状态。
- **既有状态迁移**：存量片段没有 `adoptedOwners`，第一次同步把当前主人记入（不重复加名单里已有的人），之后的删除即永久。本仓库当前状态库（已手工补过 `ou_1822…`）在升级后的首次同步只是补记，名单不变。

## 3. 行为

| 场景 | 结果 |
|---|---|
| 全新状态目录，绑定机器人 | 首次同步把主人加入名单并记录；无需第二份配置 |
| 从名单删掉一个主人（无同步群） | 永久生效：之后任何同步都不再加回 |
| dsh-im 里后来新增主人 | 下一次同步加入名单一次 |
| 设置了同步来源群 | 每次同步名单 = 群成员 ∪ 主人；手动删除会被下一次同步覆盖（花名册语义） |
| 主人身份是 `*` 或 App ID | 不进名单也不进 `adoptedOwners`：只有 `ou_` open_id 能发起工作 |
