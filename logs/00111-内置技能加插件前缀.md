# 00111 — 内置工程技能加 `eng-` 插件前缀

- **日期**：2026-11-21
- **背景**：用户要求「内建的一定得出现」。排查发现 `~/.agents/skills` 里有 34 个技能，包含内置那 27 个工程技能的中文副本（同名）；按注册表「就近层优先」的规则，preset 侧的 `skill-filesystem` 赢过 host 侧的 `skill-engineering`，于是内置版本全部被覆盖，`/` 菜单里 `mattpocock/skills` 那组是空的。
- **决定**：给随包的 27 个技能加 `eng-` 前缀（插件前缀），让两套并存、内置一定出现。

## 1. 为什么是加前缀

| 方案 | 结果 |
|---|---|
| 保持现状 | 内置技能被同名个人副本盖掉，看不见 |
| 让内置赢过就近层 | 内置出现，但用户自己的副本被静默吞掉，且推翻「就近层优先」这条架构规则 |
| **加前缀**（本方案） | 两套都在：`eng-tdd` 是内置，`tdd` 是个人副本，菜单按来源分组区分 |
| `dsh-` 前缀 | 与仓库自带的 `dsh-code-review` 撞名，内置的 `code-review` 仍会被盖，不满足「一定」 |

`eng-` 取自插件身份（包名 `skill-engineering`、provider 名 `dsh-engineering`），与 `office-*` 是同一套家族前缀写法。

## 2. 变更

| 位置 | 内容 |
|---|---|
| `packages/skill/skill-engineering/assets/` | 27 个目录改名为 `eng-<name>`，`SKILL.md` 的 frontmatter `name` 同步改 |
| 同上 | 正文里 103 处 `/名字` 命令引用改为 `/eng-名字`；`skill` 工具按名义调用（`implement`→`eng-tdd` 等）一并改 |
| `src/index.ts`、测试 | `SKILL_NAMES` 与测试里的名字列表全部加前缀 |
| 包 README（中英）、用户指南（中英）、根 README | 技能表、主流程、覆盖说明改成分前缀的说法，并写明「同名个人副本会与它并存」 |
| `snapshots/**` | 280 个 fixture 用 `test:snapshot:refresh` 重新生成（320 行），差异只有技能目录里的名字与随之变化的压缩 token 数 |

## 3. 快照

改名会改变模型可见的技能目录，已记录在 fixture 里，所以必须刷新：

```
pnpm run test:snapshot:refresh   # 270 passed, 5 failed
pnpm run test:snapshot           # 270 passed, 6 failed
```

失败的 6 个都是本机环境问题，在未改动的树上复现过，与本改动无关：

- `ptc-node-workspace`、`ptc-persistent`、`ptc-persistent-scoped`、`ptc-reset`：PTC 沙箱没有真的写出工作区文件；
- `worktree`：`snapshot Git failed: fatal: Needed a single revision`；
- `ptc-workspace-context`：fixture 里的临时目录名 `dsh-log-snap-<随机串>` 没有被归一化，每次重放都不同。

## 5. 代价与后续

- **名字与上游分叉**：上游文档写 `/tdd`，本仓库是 `/eng-tdd`。同步步骤已写进包 README：复制目录时加前缀、改 frontmatter、改正文引用。
- **模型目录变大**：11 个模型可调用技能名变长，压缩 token 数随之小幅上升（fixture 里可见），这是「两套并存」的固有成本。
- **用户侧**：`~/.agents/skills` 里的中文副本仍可用；若希望它也带前缀，需要用户自行改名，系统不会代劳。
