# 00088 — 内置工程工作流技能

- **日期**：2026-11-20
- **背景**：`nano-mattpocock-skills` 项目此前只能靠用户主目录里的符号链接进入会话，换一台机器 clone 本仓库就没有这些技能。本轮把它做成 DSH 自带能力：内容取自上游 `mattpocock/skills` 的 `main`（提交 `abeeaf9`，v1.3.2），打包进 base bundle，clone 后无需外部安装即生效。
- **范围**：`packages/skill/skill-engineering/`、`packages/bundle/base/`、`docs/`、`website/`、根 `README.md`、`logs/`。

## 1. 最终形态

- 新包 `@deepseek-ai/dsh-skill-engineering` 位于 `packages/skill/skill-engineering/`，随包 27 个技能目录和上游 MIT 许可证；提供方名 `dsh-engineering`，注册到 `ctx.skills`，排名为随包技能（600）。
- base bundle 增加 `skill-engineering` 行，`web`、`headless`、`acp`、`sdk` 四个以 base 为基础的 profile 默认挂载；在 profile patch 里把该行设为 `disabled: true` 即可整体关闭。
- 技能放在 `assets/<name>/SKILL.md`，正文里的相对引用（`tests.md`、`PHASE-BOUNDARIES.md`、`template.sh`）经 `resourceBase` 解析到各自目录。
- 调用划分沿用上游：11 个模型调用技能进入会话目录，16 个带 `disable-model-invocation: true`，只能通过输入框的 `/` 菜单触达。
- 提供方通过延迟的 `skills` 注入挂载；禁用技能注册表的组合里该行保持空闲，不再产生 pending 警告。
- 失败语义与 `skill-office` 一致：缺失（`ENOENT`/`ENOTDIR`）或无效元数据从完整目录省略并只报告一次；其他读取错误让发现不完整并从加载中抛出；同名本地技能按分层优先级覆盖内置版本。

## 2. 身份与呈现

- 包名、提供方名、组合行 id 统一为 `skill-engineering` / `dsh-engineering`，与 `skill-office` 一样按角色命名，不再带上游作者名。
- `locale/{de,en,es,fr,ja,pt,ru,zh}.json` 提供组件标题与描述，供插件清单读取；八种语言都能解析。
- 该组件挂在 base bundle，而 `HIDDEN_BUNDLES` 包含 `@deepseek-ai/dsh-base`，所以插件页面不会出现它的卡片；文档按这一事实表述，不再声称插件页入口。
- 用户指南 `docs/user/guide/engineering-skills.{md,zh.md}` 说明内置内容、调用方式、主流程、仓库配置与覆盖/移除方法；已登记到 `website/docs.ts`，中英站点分别生成 `/guide/engineering-skills.html` 与 `/en/guide/engineering-skills.html`，侧边栏排在 quickstart 之后。
- 技能名保留上游原名（`ask-matt`、`setup-matt-pocock-skills` 等），因为技能之间按名字互相引用；后续如需彻底产品化可单独改名。
