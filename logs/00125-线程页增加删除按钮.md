# 00125 — 线程页增加删除按钮

- **日期**：2026-11-23
- **背景**：00124 之后，有人被忽略的飞书消息已经从「为什么没反应」解释清楚了，接着问「刚才那个信息如何删除，还是重新发送」；说明按行清库不是人该做的事，面板里缺一个删除入口。
- **结论**：在线程页给「没有工单、没有进行中的评估、没有待决定消息」的线程加 **删除线程**（确认后调用 `POST threads/:key/delete`），一次删掉它的触发、处置、决定和关联记录；来源里的原消息不动。

## 1. 变更

| 位置 | 变更 |
|---|---|
| `src/core/model.ts` | 新增 `canDeleteThread(thread)`：没有订阅工单、没有 `evaluating`、`pending` 为空 |
| `src/core/errors.ts` | 新增 `unknownThread`（missing）与 `threadBusy`（refused）；面板按 `userError.*` 文案本地化 |
| `src/app/store.ts` | 新增 `Store.deleteThread(key)`：一个事务里删除只属于本线程的触发及其处置、本线程的触发索引与决定、线程行，并从其他线程的 `correlated` 中摘掉它；与其他线程共享的触发只删本线程的索引 |
| `src/app/runtime.ts` | 新增 `Runtime.deleteThread(key)`：先按 `canDeleteThread` 校验，再交给 Store；`unknownThread` / `threadBusy` |
| `src/app/views/threads.ts` | 线程详情返回 `deletable` |
| `src/app/http.ts`、`src/app/api.ts` | 新路由 `POST threads/:key/delete`；`HttpHost.deleteThread` |
| 客户端 | `thread.tsx` 在线程页危险区加 **删除线程**（确认后 POST、提示、回到线程列表）；`locales.ts` 补中英文与两个 `userError` |
| 测试 | 运行时：忽略的私聊线程可删、删后触发/决定/线程都没了、再删报 `unknownThread`、有工单的线程报 `threadBusy`；HTTP：路由成功与 `threadBusy` 的 400；面板：确认后真的发出 POST |
| 文档 | `docs/005-panel.md` 线程页说明、`docs/006-deployment.md` 路由表 |

## 2. 原因与判断

- **删线程而不是删一条消息**：决策记录按线程归属，单独删一条触发会留下“待评估”的空线程，反而更乱。用户要清掉的是“这条被忽略的消息”，它就是一个只有一条消息的线程。
- **只允许删空闲线程**：有工单订阅的线程是工单的上下文，删掉会让工单页和决定日志指向不存在的记录；正在评估或还有消息等待决定时删除，会让评估结果落空。三者任一存在就拒绝，并给出可操作的提示。
- **共享触发只摘索引**：一个触发可以同时属于多个线程（关联系）；这种情况下删掉触发会连带删掉另一个线程的消息，所以只删本线程在 `trigger_thread` 的索引，触发、处置和决定保留。
- **不动来源**：飞书里的原消息、dsh-im 的会话状态都不在 superagent 的删除范围内；按钮文案和文档都写明了这一点，避免以为能从面板撤回飞书消息。
- **删除后的重新建档**：来源里同一条会话再来新消息，会按原键重新创建线程；历史已删，面板从新的开始。

## 4. 未做

- 没有给主 Session 增加删除线程的工具：删除是人的整理动作，交给工具会让模型能销毁审计记录。
- 没有做“批量清理被忽略的消息”：需要先决定是按时间、按来源还是按原因筛选，属于另一个决策。
- 没有删除 `trigger_thread` 之外的审计痕迹（如面板通知），它们按工单存在，而被删线程没有工单。
