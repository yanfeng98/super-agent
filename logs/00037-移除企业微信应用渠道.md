# 00037 — 移除企业微信应用渠道

- **日期**：2026-11-17
- **背景**：用户要求把「企业微信应用」（`wecom-app`，自建应用回调模式）从原生 IM 中移除，同样要求不破坏其余渠道的正常功能。
- **范围**：`apps/web/native/dsh-im`、根 `README.md`、`packages/bundle/web-app/cordis.patch.yml`、`logs/`。

## 2. 行为

- 最终内置渠道：微信、飞书、钉钉、企业微信、QQ、iMessage、邮箱；不再有「企业微信应用」。
- 该渠道不再挂载、不再显示、不再有 RPC 与管理接口；`/api/dsh-im/wecom-app` 返回 404。
- 之前绑定的自建应用配置目录（`integrations/dsh-wecom-app`）不会再被读取，也不会让插件启动失败。
- 默认回调端口 30987 不再被占用。
- `/goal`、`/plan`、`/ws` 等命令与投递、访问策略、审批、诊断详情、侧栏显隐在其余七个渠道上不受影响。
- 「企业微信」（`wecom` 智能机器人）完全不受影响：仍是扫码接入、WebSocket 长连接、支持群聊与流式卡片。

## 4. 复查记录

- 首次跑套件 1 个失败：`channel-list-rpc` 的 `scannedFiles` 与分组断言仍按旧夹具计数。移除该渠道的 state 夹具后改为 6 个文件、四个分组，用例通过。
- 客户端词典里该渠道有 51 条专属文案。逐条确认已无引用（排除与「企业微信」共用键）后，两份词典同步删除，键集合差异与删除前保持一致。
- 未删除共享语义与通用模块；`@wecom/aibot-node-sdk` 仍由「企业微信」渠道使用，依赖不变。

## 5. 已知限制

- 变更后尚未重启当前 3080 端口的 Host 进程；重启并刷新后设置页才会只剩七个渠道。
- 包内上游 README 正文（横幅已声明为上游描述）仍提到该渠道；`docs/方案/` 下的历史方案文档按归档原则保留。
- `lib/` 不提交；新 clone 仍需 `pnpm install && pnpm run build`。
