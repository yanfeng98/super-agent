# 00058 — 修复 Web 端到端脚手架的片头遮罩与金标

- **日期**：2026-11-18
- **背景**：复核 0.2.2-rc.4 同步（00057）时，用上游的浏览器 lane（`vitest.web.config.ts`）复跑模型设置场景，19 个用例有 17 个超时失败。逐条排查后确认不是合并引入的回归，而是本仓库自身的两处长期问题被这套场景暴露出来。
- **判断依据**：失败日志显示 `dsh-boot-archive-black` 的子树在整个 30 秒重试期间持续「intercepts pointer events」；关掉片头行后同一条用例的等待从 30 秒降到 0.4 秒，其余差异只剩「IM机器人」导航项与本仓库的路由清单。
- **范围**：`apps/web/tests/scaffold.ts`、`apps/web/tests/expected/`、`logs/`。

## 1. 发现的问题

| 问题 | 表现 | 结论 |
|---|---|---|
| 启动片头遮罩 | 片头（`ui-boot-animation`）以全窗口浮层覆盖挂载点，每个场景的第一个点击都等不到可点元素，19 个用例 17 个超时 | 与本仓库产品行为一致，但上游场景不覆盖片头，也不该等它播放 |
| Superagent 启动副作用 | 内置 Superagent 在启动时创建自己的 Workspace 与主 Session，使「工作区行数」「会话行数」类断言多出 1 | 上游场景按「只有默认工作区」计数，本仓库的宿主插件改变了这个前提 |
| 设置页导航缺项 | `models-settings` 金标缺少本仓库 IM 插件的「IM机器人」导航项，11 个金标因此不匹配 | 金标早于 IM 设置页加入，之后没有再刷新 |
| WebKit 缺系统库 | 仅 WebKit 的两个用例失败（`libgtk-4.so.1`、`libgstreamer*` 等） | 本机环境缺依赖，与代码无关 |

## 2. 修复

| 位置 | 变更 |
|---|---|
| `apps/web/tests/scaffold.ts` | 新增 `FORK_ONLY_ROWS`（`ui-boot-animation`、四个 `dsh-superagent*` 行），在脚手架组合里按「该行确实存在」的条件禁用；片头浮层与宿主启动状态不再干扰上游场景，本仓库这两个插件的覆盖仍由各自的测试套件（Superagent 1271 用例、IM 的 node 测试）承担 |
| `apps/web/tests/expected/models-settings*/`、`onboarding-usable-provider/` | 用 `DSH_SNAPSHOT=refresh` 重录 12 个金标，差异仅为设置页导航新增的「IM机器人」一项 |

## 3. 验证

- `DSH_SNAPSHOT=replay vitest run --config vitest.web.config.ts`（`models-settings`、`models-settings-recovery`、`onboarding-usable-provider`、`sidebar-alignment`）：24 个用例中 22 个通过，只有 WebKit 的两个因本机缺系统库失败。
- 修复前 `sidebar-alignment` 的「工作区行数」与「会话操作字形」两条也用例失败；禁用宿主插件后 18/18 通过。
- 重录只涉及导航项一行：`git diff --stat` 为 13 个文件、21 行新增。
- `pnpm run typecheck`、`pnpm run lint` 通过；金标刷新不改变产品代码。

## 4. 结果

- 上游浏览器 lane 在本仓库重新可用，后续同步可以直接用它验证 Web 行为。
- 后续若上游再次改动设置页或侧栏结构，金标冲突只会出现在「IM机器人」这一行，便于识别。
