# 飞书补齐 dsh-im 原生读取能力

## 1. 目标

上一版把飞书入口交给 dsh-im 后，superagent 只剩一条纯文本通道：不能补收、不能看图、看不到机器人消息、没有原消息链接、重试可能重复回复。这一版把旧 lark-cli 飞书的实现原理搬进 dsh-im 的 SDK 层，不再引入 lark-cli 或第二份凭据。

## 2. dsh-im 侧

- `normalizeExternalText` 支持 `post`（富文本渲染成文本，`@` 用名字、图片写成 `[图片] img_xxx` 以便回读）和 `image`（`[图片] img_xxx` 占位）；`includeBots` 为真时放行 `app`/`bot` 发送者，事件 `actor.kind` 为 `bot`，只有 `app_id` 的机器人也能识别；post 里的 `@` 元素也参与“是否 @ 了机器人”的判断。
- `consumeInbound` 接受 `includeBots`，并把它记在独占消费者上；`acceptExternal` 按该消费者决定是否放行机器人消息。
- 新增 `dshIm` 方法：
  - `chatHistoryChecked(botId, { chatId, since, until, cursor, limit, includeBots, direct })`：按时间范围读一个群/私聊，最旧在前；
  - `threadHistoryChecked(botId, { chatId, threadId, since, cursor, limit, includeBots })`：按时间范围读一个话题；
  - `messageChecked(botId, route)`：读一条消息并返回 `message_app_link`；
  - `chatMembersChecked(botId, { chatId })`：读群成员 open_id + 名字；
  - `resourceChecked(botId, route, { fileKey, type, maxBytes })`：按上限下载图片/文件字节。
- `replyChecked` 接受 `uuid`，重试时由飞书去重。
- 生产验证缓存 tenant token（按应用身份，10 分钟或按返回的 expire），每次仍读取机器人身份，所以远端身份变化仍会立即报 `account-changed`。
- 新增读取都要求独占消费者租约，并校验账号 fingerprint；`historyChecked` 的 `includeBots` 也已支持。
- 历史读取现在包含机器人消息（`includeBots`）和富文本/图片占位；机器人消息仍按 `sender_type` 标记，不会变成人类消息。

## 3. superagent 侧

- 新增 `src/sources/feishu-im-loops.ts`：
  - 每 60 秒按游标补收配置的群和已知私聊（首次回看 10 分钟），逐页读到没有 `nextCursor`；
  - 轮询已订阅线程，按线程游标补收；
  - 补收的消息与实时事件共用 Trigger id，`Intake` 去重，重叠不会产生重复工单；
  - 健康状态写入新增的 `history` 条目；
  - 每轮把 dsh-im 的群投递目标名称合并进 `KV.sources.labels`，群名会随补收自动更新；
  - 游标只在读完整页后推进到 `now`（回退 5 秒）；达到单轮页数上限时推进到最后一条消息（同样回退 5 秒），不会跳过窗口，也不会因最终一致性漏消息。
- `imTrigger` 用 `withMentionNames` 把 `@_user_1` 换成 `@名字`；机器人发送者 `human: false`；`meta` 记录 `messageType`、`images` 和 `bot`。
- 上下文消息（`eventView`）同样替换 `@` 名字，并带上 `bot` 标记和 `reply_to`，模型能分清谁说的、在回复谁。
- 图片：`readFeishuImImage` 通过 `resourceChecked` 下载、按魔数判断 PNG/JPEG/GIF/WebP，再作为附件交给模型；`threadContext` 恢复 `images`/`image` 钩子。
- 策略恢复 `bots`（机器人消息作为候选）和 `syncChat`（从群成员同步允许名单）。
- 来源链接：`sourceLink` 先通过 `messageChecked` 取原消息 AppLink，失败再退回 `feishu-im/<trigger>/thread` 资源。
- `refreshLabels` 现在会把读到的名字写入 `KV.sources.labels`，面板的群名选择器不再总是空。
- 回复：`sendFeishuIm` 用消息 id 作为 `uuid`；`reply-result-unknown` 交给 outbox 重试，同一 `uuid` 由飞书去重，既不丢回复也不重复。
- 机器人品牌按 `botId` 缓存，切换机器人后旧工单的 Lark/Feishu 链接不会用错域名。
- 历史与实时事件都带 `includeBots: true`，机器人消息进入评估前仍受 `policy.bots` 约束。

## 4. 行为与限制

| 场景 | 结果 |
|---|---|
| superagent 或 Host 重启 | 下一轮补收按游标读回缺失消息，实时与补收按 Trigger id 去重 |
| 用户在群里发图片 | dsh-im 渲染为 `[图片] img_xxx`；评估可调用图片读取，按权限和模型能力下载 |
| 富文本（post） | 渲染为标题 + 段落文本，`@` 用名字、图片保留 key；post 里 @ 机器人也算 addressed |
| 群里的机器人消息 | 实时与补收都可见；只有 `policy.bots` 名单里的机器人能成为候选，且不能发起明确请求 |
| 重试回复 | 同一消息 id 作为 `uuid`，飞书去重；结果不确定时重试而不是丢弃 |
| 读取全部群消息 | 仍取决于飞书应用权限（`im:message:readonly`、`im:resource`、获取群组中所有消息） |

独占模式不变：接管期间 dsh-im 自己的卡片、斜杠命令和普通会话仍暂停。

## 6. 审计修复

实现完成后又逐项自查了一遍，发现并修复以下问题：

- **post 图片读不了**：`renderPostElement` 只输出 `[图片]` 不带 `img_` key，`readFeishuImImage` 的 key 校验永远失败；改为 `[图片] img_xxx` 并补测试。
- **post 里 @ 机器人不算 addressed**：`message.mentions` 可能为空；渲染时收集 `@` 的 user_id，参与 `mentionedAccount`。
- **只有 `app_id` 的机器人发送者被拒**：`normalizeExternalText` 只读 `sender_id.open_id`，会抛 `invalid-inbound` 丢掉整条消息；`includeBots` 时回退到 `app_id`。
- **上下文丢标记**：`eventView` 不替换 `@`、没有 `bot` 和 `reply_to`；补齐。
- **结果不确定的回复被静默丢弃**：`reply-result-unknown` 原来当成已发送；改为交给 outbox 重试，靠 `uuid` 去重。
- **补收游标跳过窗口**：达到单轮 20 页上限时仍把游标推到 `now`，剩余消息永久丢失；改为只推进到实际读到的最后一条（回退 5 秒）。
- **多机器人品牌串用**：`cachedBot` 单例导致旧工单链接可能用错 Lark/Feishu 域名；改为按 `botId` 缓存。

## 7. 未覆盖

- 真实飞书租户端到端仍未跑；补收和图片依赖应用权限，需要在租户里实测。
- 回复仍是纯文本（dsh-im `replyChecked` 目前只发 `text`），旧版的 `--markdown` 富文本回复没有恢复。
