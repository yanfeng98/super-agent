# 00059 — 合并检查门、可编辑标签与评审备注

- **日期**：2026-11-18
- **背景**：复核发现文档承诺“配置检查后合并要求通过”，但 `Runtime.mergeTicket` 从未调用 `mergeBlockedByCheck`；同时工单标签只能创建时设置，评审备注没有解决状态，搜索缺少日期限定。本日志记录这一轮的修复与验证。

## 1. 合并检查门

- `src/app/runtime.ts` 的 `mergeTicket` 在调用 `mergeWorkspace` 前执行 `mergeBlockedByCheck(executor.check, ticket.checks, ticket.ended.at)`，失败返回 400 文本，面板与管理 API 走同一路径。
- 新增 `tests/runtime.spec.ts` 集成用例：失败检查、结束前通过的检查都不能合并；通过且晚于结束的检查才放行。
- 文档 `docs/003`、`docs/005` 的“检查挡住合并”从承诺变为实际行为。

## 2. 可编辑标签

- `Ticket.tags` 与 `Ticket.tagged` 新增；`Tickets.setTags`、`Engine.setTags`、`Runtime.setTags`、`POST tickets/:id/tags` 完成替换，空数组表示清空，最多 8 个、每个 1–24 字符。
- 读取标签优先用 `ticket.tags`（存在即使用，空数组不回退），否则回退到起始 Trigger 的 `meta.tags`；列表筛选、搜索与标签汇总共用这一规则。
- 面板工单页新增 **Edit labels** 表单与操作历史 `tagged` 项；本地归档追加 **Tags** 段，启动对账也会补写。
- 新增 `invalidTags` 用户错误与中英文案；`views.spec`、`core-engine.spec`、`local.spec`、`http.spec`、`panel-execution.spec` 覆盖。

## 3. 评审备注解决状态

- `TicketNote.resolved` 新增；`Tickets.resolveNote`、`Engine.resolveNote`、`Runtime.resolveNote`、`POST tickets/:id/notes/:noteId/resolve` 支持标记已解决/重新打开。
- 合并前拒绝任何未解决备注；面板显示未解决数量，发送给执行器时只发送未解决备注。
- 归档的评审备注仍只在工单数据库中，不新增归档段。

## 4. 搜索日期限定与分页

- `created:` 与 `updated:` 支持日期或完整时间戳，可带 `>=`、`<=`、`>`、`<`、`=`；`label:` 作为 `tag:` 的别名。
- 非法日期和未知 `is:` 值保留为自由文本，不会静默匹配全部。
- 工单结果每页 50 条，`GET search` 接受 `offset` 并返回 `next_offset`；面板显示 **Load more** 并追加下一页。
- 文档 `docs/005`、`docs/006` 的搜索说明同步。

## 5. 批量标签与检查历史

- Execution 列表的选择区新增批量标签输入与按钮，对每个选中工单调用 `POST tickets/:id/tags`；结果沿用批量完成/失败提示。
- `Ticket.checkHistory` 保留最近 10 次检查运行，`checkTicket` 与结束时检查都会写入；面板在检查区块折叠显示历史。

## 6. 评审结论与合并门

- `Ticket.reviewed` 记录 `approved` / `changes-requested` 与可选说明；`Tickets.review`、`Engine.reviewTicket`、`Runtime.reviewTicket`、`POST tickets/:id/review` 完成写入，并在本地归档追加 **Review** 段。
- 要求修改的评审始终阻止合并；`executor.requireReview`（默认关闭）开启后，没有批准的评审也会阻止合并。重开或变基会清空评审结论。
- 面板工单页在 Changes 区显示 **Approve changes** / **Request changes** 与当前结论；Execution 设置新增 **Require review approval** 开关。
- 新增 `reviewNeedsEnded` 用户错误与中英文案；`core-engine.spec`、`runtime.spec`、`http.spec`、`panel-execution.spec` 覆盖。
