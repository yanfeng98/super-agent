# 00025 — 移除 zai 供应商

- **日期**：2026-11-16
- **背景**：`zai` 是 pi-ai 目录中的 Z.AI 国际站编码套餐路由（名称 Z.AI），以 `openai-completions` 接入 `https://api.z.ai/api/coding/paas/v4`，只有 API key 鉴权（`ZAI_API_KEY`），没有 OAuth。同族的 `zai-coding-cn` 是它的中国站编码套餐（`https://open.bigmodel.cn/api/coding/paas/v4`，`ZAI_CODING_CN_API_KEY`），两者协议与兼容性设置完全一致。`zai` 目录快照 7 个模型（`glm-4.7`、`glm-5-turbo`、`glm-5.2`、`glm-5.2-highspeed`、`glm-5.3`、`glm-5.3-flash`、`glm-5.3-highspeed`），`zai-coding-cn` 4 个（`glm-4.6v`、`glm-5.3`、`glm-5.3-flash`、`glm-5.3-highspeed`），重合的 3 个 id 价格、上下文与输出上限完全相同。用户要求只保留国内路由，按既有 `WITHHELD_PROVIDERS` 机制移除国际站路由。
- **范围**：`packages/llm/llm-pi-ai`（目录控制点与测试）、`docs/user/guide/providers.md`、`packages/llm/llm-pi-ai/README.md`、升级指南、Web golden、根 README 与 `logs/`。

- **后续变更**：`baseten` 已于 [00026](00026-移除baseten供应商.md) 移除，本记录表格中的 `baseten` 承接路由不再可用；`glm-4.7` 现在只由 `openrouter`（`z-ai/glm-4.7`）提供，其余模型的承接路由不变，现行覆盖见该文件第 3 节。

> **后续变更**：`apps/web/native/dsh-im/` 已由 [00027](00027-原生集成dsh-im.md) 与 [00028](00028-移除四渠道.md) 正式纳入原生 IM；`verify-concrete-terms` 的最终处理是该目录的 vendored 子树例外，相关门禁现已通过。

## 2. 行为

- 可对话供应商 21 → **20**，目录模型 710 → **703**（只减 `zai` 的 7 个模型）。
- `catalogProvider('zai')` 返回 `undefined`，`catalogModels('zai')` 为空；目录、模型解析、发现、登录与可配置供应商列表都不再出现该路由。
- 存量 profile 点名 `zai` 时 `resolveProfiles()` 在 strict 与 deferred 下都抛 `llm-pi-ai: provider "zai" is removed from this build; delete the route or select another provider`，同一 `providers` 字典里的其他路由随之不可用，删除该条目即恢复。
- `zai-coding-cn` 仍以 4 个模型提供，`ZAI_CODING_CN_API_KEY` 与 `https://open.bigmodel.cn/api/coding/paas/v4` 不变。
- `provider-data.generated.ts` 仍保留 42 个 id 的元数据（`verify-provider-data` 要求与已安装目录一致），它不是可售路由；内置 id 现为 42 = 20 个提供 + `typesafe` + 21 个被移除。

## 3. 模型覆盖

| 模型 id | 推理 | 价格（输入/输出，$/M） | 上下文 | 最大输出 | 移除 `zai` 后的其他内置路由 |
|---|---|---|---|---|---|
| `glm-4.7` | 是 | 0.6 / 2.2 | 204,800 | 131,072 | `baseten`（`zai-org/GLM-4.7`）、`openrouter`（`z-ai/glm-4.7`） |
| `glm-5-turbo` | 是 | 1.2 / 4.0 | 200,000 | 131,072 | `openrouter`（`z-ai/glm-5-turbo`） |
| `glm-5.2` | 是 | 1.4 / 4.4 | 1,000,000 | 131,072 | `opencode-go`（同 id）、`baseten`、`openrouter`、`together`、`mistral` |
| `glm-5.2-highspeed` | 是 | 目录未标价 | 1,000,000 | 131,072 | 无 |
| `glm-5.3` | 是 | 1.4 / 4.4 | 1,000,000 | 131,072 | `zai-coding-cn`（同 id）、`baseten`、`fireworks`、`opencode-go`（同 id）、`openrouter`、`together`、`mistral` |
| `glm-5.3-flash` | 是（`text+image`） | 0.15 / 0.5 | 1,000,000 | 131,072 | `zai-coding-cn`（同 id）、`baseten`、`fireworks`、`opencode-go`（同 id）、`openrouter`、`together` |
| `glm-5.3-highspeed` | 是 | 目录未标价 | 1,000,000 | 131,072 | `zai-coding-cn`（同 id） |

重合的 3 个 id 在两条 Z.AI 路由上的价格、上下文、输出上限与兼容性设置完全一致，切换路由不改变模型行为。`glm-4.7` 与 `glm-5-turbo` 在 `openrouter`（以及 `glm-4.7` 在 `baseten`）上以不同 id 提供，`glm-5.2` 另有 `opencode-go`（同 id）、`baseten`、`openrouter`、`together` 与 `mistral`，只有 `glm-5.2-highspeed` 没有其他内置路由。7 个模型都可按 `openai-completions` 自定义模型 API 接入 `https://api.z.ai/api/coding/paas/v4`，但需要国际站账号的 key，国内站 key 不能替代。

## 5. 复查记录

- 沿用 `minimax` 的先例处理「国际站 / 中国站」成对路由：保留中国站而非整体移除，因为重合的 3 个同 id 模型在两条路由上价格与能力一致；同时如实记录只有 `glm-5.2-highspeed` 没有其他内置路由、其余模型仍在 `baseten`、`openrouter`、`opencode-go` 等路由上可用。
- 目录顺序核对：`zai` 在内置目录中排在 `zai-coding-cn` 之后（字母序亦相同），因此 `WITHHELD_PROVIDERS` 与各文档清单都放在列表末尾。
- `docs/user/guide/providers.md` 第 19 行原先用 `zai` 作为「GLM 对应 id」的示例；该 id 已被移除，改为 `zai-coding-cn`，避免文档示范一个不存在的路由。
- 升级指南原为 496 词，追加 `zai` 必然越限，因此把迁移段改写为三段式（协议与端点、仍由其他路由承接、失去内置路由的模型），把逐路由明细压缩为分组陈述，落到 463 词，事实未减：`nvidia` 十一个独有、`huggingface` 14/78、`ant-ling` 3 个、`opencode` 5 个付费独有另加 8 个免费档、`xiaomi` 2 个 UltraSpeed 变体、`radius` 三个别名、`vercel-ai-gateway` 118/301 与其余 183 个独有 id 均保留。
- Web e2e 失败归因经单独回放确认，覆盖层来自并行开发已提交的 `@deepseek-ai/dsh-client-ui-boot-animation`，不是本次移除引入；golden 的正确性因此改用脚本对比验证。
- 与上一轮不同，本轮 `build` 报告 11 个门禁（此前 10 个），门禁列表由仓库脚本决定，与本次改动无关。
- 工作区在移除与校验期间被并行开发提交（`feat(im)`，带入根 README 与 `apps/web/native/dsh-im/`），因此根 README 的三处数字改动随该提交进入 `main`，本轮的移除提交只含其余文件；`verify-concrete-terms` 随该提交变红，与本次移除无关，未在本轮处理。

## 5a. 审计轮修正

- 复查本轮改动时发现并修正 6 处：§3 的 `glm-5.3-flash` 行漏记 `opencode-go`（该路由同样以同 id 提供）；§6 的「失去全部内置路由」措辞（改为「没有其他内置路由」）；§6 的「内置的两个 Z.AI 路由」（移除后目录里只剩国内站一条）；§4 的配对数量（最终为 4 对）；升级指南覆盖段补全 `opencode` 的 8 个免费档模型、`xiaomi` 的 2 个 UltraSpeed 变体与 `vercel-ai-gateway` 的 183 个独有 id，并把「Some」枚举改为「for example」以明确非穷尽；`00009` 的 `nvidia` 行曾把 `zai` 列为可用路由，改为 `zai-coding-cn`（`z-ai/glm-5.3` 与 `z-ai/glm-5.3-flash` 确由国内站承接）。
- 复核修正了本轮最实质的一处错误：初稿把 `glm-4.7`、`glm-5-turbo`、`glm-5.2-highspeed` 一并写成「没有其他内置路由」。按名称与 id 逐路由比对后发现，`glm-4.7` 在 `baseten`（`zai-org/GLM-4.7`）与 `openrouter`（`z-ai/glm-4.7`）上、`glm-5-turbo` 在 `openrouter`（`z-ai/glm-5-turbo`）上、`glm-5.2` 在 `opencode-go`（同 id）、`baseten`、`openrouter`、`together` 与 `mistral` 上同样可用，真正没有其他内置路由的只有 `glm-5.2-highspeed`；目录注释、用户指南、包 README、升级指南、根 README 与本日志的表格已同步改正，指南随后由 457 词增至 463 词。
- 复核未变的数据：20 个供应商 / 703 个模型；三个重合模型（`glm-5.3`、`glm-5.3-flash`、`glm-5.3-highspeed`）在 `zai` 与 `zai-coding-cn` 上的价格、上下文、输出上限与 `compat` 逐字段相同。

## 6. 已知限制

- `glm-4.7`、`glm-5-turbo`、`glm-5.2-highspeed` 没有其他内置路由；`glm-5.2` 只剩 `opencode-go`。要继续使用国际站原服务，需以 `openai-completions` 自定义模型 API 接入 `https://api.z.ai/api/coding/paas/v4`，Provider ID 需避开 `zai`，并使用国际站账号的 key。
- 目录里的两个 Z.AI 路由（国际站已被本构建移除）都指向 Coding Plan 订阅端点（路径 `/api/coding/`）；按量计费的 `/api/paas/v4` 端点没有内置路由，需要的用户需自行添加自定义路由。
- 国内站 `zai-coding-cn` 的目录只含 4 个模型；`glm-4.6v`（`text+image`，128,000 上下文、32,768 输出）是它独有的视觉模型，其他 3 个与本次移除的 `glm-5.3`/`-flash`/`-highspeed` 重合。
- 运行中的 `127.0.0.1:3080` 进程需要重启才会反映目录变化。
