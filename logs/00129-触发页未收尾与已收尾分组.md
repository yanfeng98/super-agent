# 00129 — 触发页区分「未收尾」与「无需合并/已收尾」

- **日期**：2026-11-25
- **背景**：触发页的「未收尾」把已完成但无需合并的调查/本地修复，以及用户明确放弃的工单都算了进去。T-0020、T-0017 标「已完成」、T-0002、T-0003 标「已放弃」，实际都已收尾，却和真正需要合并/推送的工单混在一段。
- **结论**：把触发页线程分成三段：仍需合并或推送的进 **未收尾**；已完成无需合并、用户放弃/丢弃、已合并且推送成功的进 **无需合并 / 已收尾**；没有工单的普通会话进 **其他线程**。

## 2. 原因与判断

- **以「是否还需要合并或推送」为准**：原来把「没有合并」直接等同于「未收尾」，把纯调查和用户放弃误判。现在按工单事实分类：合并回退、推送失败、关闭未合并、有待处理的合并请求（standing merge 或合并队列）、以及尚未结束的工单留在未收尾；完成且无人要求合并、放弃、丢弃、无需处理、合并成功且推送成功都算收尾。
- **待合并请求特殊处理**：`completed` 工单若仍有 `autoMerge` 或排队中的合并请求，说明有人要求它落地，仍算未收尾。
- **普通会话不进任何工单分组**：没有订阅工单的线程没有需要落地的工作，单列「其他线程」。
