# 00049 — 修复审计发现

- **日期**：2026-11-18
- **背景**：对 00042–00048 的改动做复核，发现若干功能与一致性问题；本日志记录发现与修复。
- **范围**：`apps/web/native/dsh-superagent`（`src/core/*`、`src/app/*`、`src/sources/local.ts`、`src/executor/dsh.ts`、`docs/`、`tests/`）。

## 1. 发现与修复

| 问题 | 影响 | 修复 |
|---|---|---|
| 本地来源的 `webhook`、`projects` 只有 schema，没有 `fields` | 面板无法配置，保存来源设置时还可能丢失 | `localKind.fields` 补上 Webhook 与项目行（名称/根目录/prepare），根目录列可选 |
| 批准 held 工单时不重新校验 Mandate | 策略撤销后仍能批准并启动执行器 | `Tickets.approve` 增加 `policy().revalidate`，撤销时抛 `mandateRevoked`，hold 保留 |
| 批准时没有待运行派工用了 `notRetryable` | 错误文案误导为「重试」 | 新增 `notPending` 及中英文案 |
| 丢弃的工单仍可重新打开 | 工作区已删除，重开会启动到空目录 | `Tickets.reopen` 拒绝 `discarded`（`ticketDiscarded`），详情页不再显示 Reopen |
| 合并可重复执行 | 重复写归档、重复报告成功 | 已合并的工单再次合并直接报错 |
| 附件写完后 `ctx.receive` 抛错不清理 | 留下无人读取的归档与附件 | 捕获后删除归档文件和 `<request>.files/`；新增测试 |
| 附件文件名允许控制字符 | 可破坏归档 Markdown 结构 | HTTP 与本地写入都拒绝/替换控制字符；新增测试 |
| 结束/问题/重开的外部副作用在事务提交前发生 | 事务回滚也可能已发 Webhook 或写归档 | 改为 `store.afterCommit`；`finishTicket` 在采集前后检查工单仍以同一时间结束，避免与 follow-up 恢复竞态 |
| 重启对账可能与 follow-up 恢复竞态 | 给已恢复的工单补写关闭段 | 写关闭段前重新读取，结束时间不一致则跳过 |
| 文档领域事件列表缺少新事件 | 文档与代码不一致 | 007 补 `ticket.reopened`、`ticket.approved`、`ticket.attention` |

另清理了标签视图中的 `unknown[]` 断言，并给执行器的项目根目录加了绝对路径校验。
