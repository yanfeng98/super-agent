# 00076 — 回退合并、批量合并与更宽的通知

- **日期**：2026-11-19
- **背景**：00075 之后对照 GitHub，还差三块：已合并的工单不能回退、一次只合一件、通知只覆盖“等待回复/结束”。这轮补齐。
- **范围**：`src/app/review.ts`、`src/app/runtime.ts`、`src/app/notifications.ts`、`src/app/passes.ts`、`src/app/webhook.ts`、`src/app/tools/main.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/app/views/tickets.ts`、`src/core/model.ts`、`src/sources/local.ts`、`src/client/ticket.tsx`、`src/client/locales.ts`、`docs/001`–`007`、`README.md`、`NATIVE.md`、`tests/`。

## 1. 回退合并

- `TicketMerge` 新增 `root`（合并所在仓库），`mergeWorkspace` 返回值带上它；这样即使 worktree 已经被清理，回退仍然知道在哪个仓库跑 git。
- 新增 `revertWorkspace`：在目标分支上 `git revert --no-edit`，合并提交（两个父）用 `-m 1`；先确认提交存在，再检查仓库分支与提交残留，失败时 `git revert --abort`，有未合并文件就抛 `RevertConflictError`。
- `Runtime.revertTicket(id, origin)`：只对已合并且未回退的工单开放，记录 `Ticket.reverted = { at, commit, target, merge, via }`，本地归档追加 **已回退** 一节，并留下 `reverted` 通知。同一工单的并发回退有在跑标记。
- 面板：已合并的工单多一个 **回退合并** 按钮（二次确认），历史里出现“回退合并”并显示反向提交短 SHA。
- 主会话：新工具 `orchestrator_ticket_revert`（19 → 20 个工具），接受 `T-0007` 这样的编号。

## 2. 一次合并多件

- `orchestrator_ticket_merge` 增加 `ticket_ids`（1–10 个），与 `ticket_id` 二选一；按给定顺序逐个走同一套闸门，每件单独返回 `{ticket_id, branch, target, head?}` 或 `{ticket_id, error}`，一件失败（例如冲突已交回它的 worker）不影响后面的条目。
- 串行执行意味着一次工具调用可能较久；这与“说一句话就合并”的用法一致，结果在同一条回复里逐条给出。
- 面板不加批量合并按钮：面板仍以记录和 review 为主，批量动作留给聊天。

## 3. 通知补齐

- 通知类型从 `attention | ended` 扩到再加上 `merged`、`reverted`、`review`、`ci`、`automerge`。
- 来源：
  - 合并落库后记 `merged`（含推送失败原因），无论来自聊天、面板还是自动合并；
  - 回退后记 `reverted`；
  - 工单以 `completed` 结束、且部署要求评审时记 `review`；
  - pass 每 15 秒扫一次已结束未合并、跟随 PR 的工单，`ci.problem` 首次出现（或文案变化）记 `ci`，靠 `Ticket.ciNotice` 去重；
  - 自动合并第 8 次失败放弃时记 `automerge`。
- 本地工单的 webhook 现在也发这五类事件（`event` + `ticket` + `text`），失败只记日志。
- 桌面通知保持不变：仍只在“开始等人”“结束”时打扰浏览器；新类型进的是面板收件箱。

## 4. 测试

- `tests/review.spec.ts`：真实 git 上的 fast-forward 回退、合并提交回退、冲突回退（分支不动、工作区干净）、脏仓库/未知提交/错分支的拒绝。
- `tests/merge.spec.ts`：`merged.root` 与 `merged` 通知；回退记录、二次回退拒绝、冲突回退报错；CI 通知只报一次、结果变化再报一次；自动合并放弃也留通知。
- `tests/chat-tools.spec.ts`：`ticket_ids` 逐个调用、失败继续、二选一校验；回退工具。

- `tests/panel-execution.spec.tsx`：合并工单上的 **回退合并** 按钮发出 `POST tickets/<id>/revert`。

## 7. 仍然存在的差距

- 回退是“撤销那一次合并”，不做“再用一个工单把回退做完”的关联工单。
- 批量合并是同步串行，不是可排队的合并队列；一件卡在检查上会拖住后面的条目。
- 没有合并后对目标分支再跑检查；没有按人分配评审人/CODEOWNERS；diff 仍是整段字符串。
