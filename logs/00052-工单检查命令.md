# 00052 — 工单检查命令与合并门

- **日期**：2026-11-18
- **背景**：对比 GitHub 的第 4 项差距：本地工单合并前没有任何校验，测试/构建结果不影响合并。本日志记录可配置的检查命令与合并门。
- **范围**：`apps/web/native/dsh-superagent`（`src/app/check.ts`、`src/app/runtime.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/app/views/tickets.ts`、`src/policy.ts`、`src/app/settings.ts`、`src/app/settings-history.ts`、`src/core/*`、`src/sources/local.ts`、`src/client/*`、`docs/`、`tests/`）。

## 1. 改动

| 项 | 内容 |
|---|---|
| 设置 | `executor.check`（空 = 不检查）；Settings → Execution 新增「检查命令」，配置历史新增 `change.checkCommand` |
| 运行 | 工单每次结束时用 `sh -c` 在 worktree 运行，带执行环境变量；记录 `checks: { command, ok, exitCode, at, output, truncated? }`，超时按失败计，输出保留末尾 4000 字符 |
| 手动重跑 | `POST tickets/:id/check` 与工单页 **Run check**，用于修完问题后确认 |
| 合并门 | 配置了检查命令时，**Merge** 要求最近一次检查通过；否则报错提示先运行检查并修好。未配置检查命令时行为不变 |
| 归档 | 关闭段追加 `- check: passed/failed (exit N)` 与 `- check_command: …` |
| 重开 | 合并后清理过工作区的工单拒绝重开（新错误 `ticketCleaned`），面板不显示 Reopen |
| 视图 | `checks`、`actions.check`；工单页显示状态、命令、运行时间、输出与截断提示 |
