# 00051 — 工单全文、变基与合并后清理

- **日期**：2026-11-18
- **背景**：与 GitHub 对比后列出 12 项差距，本日志记录第 1–3 项的修复：工单页只显示请求预览、只支持快进合并且失败信息不可行动、合并后无法清理 worktree。
- **范围**：`apps/web/native/dsh-superagent`（`src/app/views/tickets.ts`、`src/app/review.ts`、`src/app/runtime.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/client/ticket.tsx`、`src/core/model.ts`、`src/sources/local.ts`、`docs/`、`tests/`）。

## 1. 改动

| 问题 | 修复 |
|---|---|
| 工单页只显示 160 字请求预览，附件路径与附件列表都看不到 | `ticketDetail` 的触发输入新增 `body`（完整纯文本），页面用 `ClampText` 折叠展示，展开可读全文；`GET tickets/:id` 增加 `archive`，标识区显示归档文件路径 |
| 合并失败时只抛 git 的裸错误 | `mergeWorkspace` 先用 `git merge-base --is-ancestor` 判断能否快进，不能时直接提示「目标分支有工单分支缺少的提交，先变基再合并」 |
| 仓库前进后无变基入口 | 新增 `rebaseWorkspace`、`POST tickets/:id/rebase` 与工单页的 **Rebase**；变基只改写工单分支，冲突时执行 `git rebase --abort` 保留原提交，成功后重新采集 review |
| 合并后 worktree 与已合并分支无法清理 | 新增 `cleaned` 记录、`POST tickets/:id/cleanup` 与 **Clean up worktree**；删除分支时用 `git branch -d` 的安全检查，提交已进入目标分支才允许删除，并追加归档「已清理」段 |

相关细节：

- `discardWorkspace` 增加 `{ merged }` 选项：合并后的清理走 `-d`，未合并的丢弃仍是 `-D`。
- `recordCleanup` 写入 `<!-- dsh-superagent:cleaned:<time> -->` 生命周期段。
- 视图层新增 `actions.rebase`、`actions.cleanup` 与 `cleaned` 字段；合并提示与清理按钮不再依赖 review 是否存在。
- 新增 locale：`archiveFile`、`ticketRebase`、`rebaseTitle`、`rebaseConfirm`、`cleanupWorktree`、`cleanupTitle`、`cleanupConfirm`、`cleanedHint`。
