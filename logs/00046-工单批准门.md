# 00046 — 工单批准门

- **日期**：2026-11-18
- **背景**：新建工单会立即启动执行器。对于从脚本/命令行排队、或希望先检查再执行的请求，需要一个明确的「批准后才跑」的停顿点。
- **范围**：`apps/web/native/dsh-superagent`（`src/core/*`、`src/executor/dsh.ts`、`src/app/*`、`src/sources/local.ts`、`src/client/*`、`docs/`、`NATIVE.md`、`tests/`）。

## 1. 变更

| 位置 | 变更 |
|---|---|
| `src/core/model.ts`、`src/core/stage.ts` | `Ticket.hold`；阶段新增 `person/approval`（在 delivery/answer/review 之前） |
| `src/core/tickets.ts`、`src/core/engine.ts` | `Tickets.approve` / `Engine.approveTicket`：清除 hold、启动待运行派工；未 hold 或非待运行派工时报错（`notHeld`/`notRetryable`）；新增 `ticket.approved` 事件 |
| `src/executor/dsh.ts` | `prepare` 从 Trigger 的 `meta.hold` 设置 hold；`start` 对有 hold 的工单不入队 launch |
| `src/sources/local.ts` | 请求支持 `hold`，写入 front matter 与 Trigger meta；归档新增「批准 / Approved」段；inbox 支持 `hold` |
| `src/app/http.ts`、`src/app/api.ts` | `POST local/requests` 接受 `hold`；新增 `POST tickets/:id/approve` |
| `src/app/views/tickets.ts` | 工单详情返回 `actions.approve` |
| `src/client/execution.tsx`、`src/client/ticket.tsx` | 新建工单增加「先审阅再执行」；待批准工单页显示 **批准执行** |
| `src/client/locales.ts`、`src/client/marks.ts`、`src/app/cards.ts` | `stage.approval`「待批准」、批准按钮文案、阶段图标与卡片状态 |
| `docs/003/005/006`、`NATIVE.md` | 阶段表、面板、部署与本地改动说明 |
| `tests/stage.spec.ts`、`tests/local.spec.ts`、`tests/http.spec.ts`、`tests/panel-execution.spec.tsx` | 覆盖 hold 阶段优先于 delivery、请求 hold 元数据、批准清 hold 并启动派工、重复批准报错、路由和面板按钮 |
