# pi-ai 升级到 1.6.0

## 1. 目标

`openai-codex` 路由的模型列表停留在 `@earendil-works/pi-ai` 1.3.0：缺少 GPT-6.1 Terra、GPT-6.2 Astra、GPT-6.2 Sol，并且仍在展示上游已因 ChatGPT 账号被后端拒绝而移除的 `gpt-5.5` 与 `gpt-5.3-codex-spark`。把适配器升到 1.6.0，让目录与上游一致。

## 2. 依赖更新

- `packages/llm/llm-pi-ai` 的 `@earendil-works/pi-ai` 由 `^1.3.0` 改为 `^1.6.0`，锁文件解析到 1.6.0（`pi-telemetry` 同步到 1.6.0）。
- `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 与 `patchedDependencies` 的版本键改为 1.6.0。
- 桌面打包的补丁策略（`apps/desktop/scripts/runtime-patch-policy.ts`）、`THIRD_PARTY_NOTICES.md` 指向新补丁。
- `experimental/subagent-oar` 仍声明 `^1.3.0`，它不导入 pi-ai，按原版本保留，工作区内同时存在两份 pi-ai 属预期。

## 3. 补丁

`patches/@earendil-works__pi-ai@1.6.0.patch` 取代 1.3.0 版本，只剩一件事：把 OpenAI 兼容流里的 Gemini 思考签名（`tool_calls[].extra_content.google.thought_signature`）读入工具调用的重放签名，并在同一模型继续时发回。

原补丁的其余 5 处（移除各流适配器逐 delta 重解析参数 JSON）已由上游 1.5.0 的增量解析器（earendil-works/pi#9265）正式修掉，不再需要补丁。

## 4. 代码调整

- 新增 compat 漂移门分类：`requiresNonNullAssistantContent`、`requiresToolsWithToolHistory`、`promptCacheKeyMode`、`supportsMessageThreads`、Mistral 的 `supportsStrictMode`，并在 `PiAiCompatProfile` 与配置 schema 中开放（`promptCacheKeyMode` 用 `auto|enabled|disabled` 联合），在 `compat-upgrade.spec.ts` 中为每个开关补了接受与拒绝用例。
- `chat_template_kwargs` 的 `$var` 值新增无 `omitWhenOff` 的分支：pi-ai 把缺省视为 false，上游类型也已把它改为可选。
- `EveryProfileFieldMatchesUpstream` 比较前去掉双方显式 `| undefined`：pi-schema 渲染的可选字段带显式 `undefined`，与本地 `?:` 写法在 `exactOptionalPropertyTypes` 下不再双向可赋值。
- 重新生成 `provider-data.generated.ts`：新增 `qwen-token-plan-individual-cn`，Qwen Token Plan 三条路由换成新的网关地址与计划级密钥变量。

## 5. 行为变化

- `openai-codex` 目录：新增 GPT-6.1 Terra、GPT-6.2 Astra/Sol；移除 `gpt-5.5`、`gpt-5.3-codex-spark`（后端拒绝，属修复）。已保存指向这两个 id 的模型选择需要改选。
- Codex 路由的工具增量改用 `additional_tools` 输入项，顶层不再发送 `tools` 数组。
- `openai-completions` 只对 `api.openai.com` 发送 `developer` 角色，其余主机（含私有网关）默认 `system`；`supportsDeveloperRole` 可覆盖。
- 流式工具参数每个 delta 的 partial 携带至今为止的参数，不再恒为 `{}`；本适配器只读取 delta 字符串与最终参数。
- `gpt-5.4` 不再声明 `additional_tools`/`toolSearch` 通道，其工具变更按基线重建，不再有 developer 更新消息。
- 服务端的 `anthropic` 路由（`api.anthropic.com`）改用 Anthropic message threads（beta `message-threads-2026-08-12`）：agent loop 传 `sessionId`，请求按需只发送新增消息，历史由服务端续接；输入前缀变化时 pi-ai 退回完整请求。私有网关协议默认不启用，可用 `supportsMessageThreads` 打开或关闭。

## 6. 文档

- 包 README（中英）、用户指南的 providers 页（中英）与 `catalog.ts` 的 `WITHHELD_PROVIDERS` 注释原本各自复述了一份逐路由模型清单，且里面的总数、重叠数、`:free`/`:batch`/前缀拆解在 1.3.0 时就已经与安装目录不一致。这次统一改写成不随目录漂移的稳定事实：路由集合、四组不提供的原因、已由哪条路由或哪个端点承接，端点与协议只在包 README 中列一次，其余位置链接过去。
- 新增升级指南 `docs/upgrade-guide/v0.2.2-rc.5/pi-ai-catalog-model-removals/`（中英 + 配对记录），说明被移除的目录 id 与迁移动作。
- 根 `README.md` 的「与上游的差异 / 新增与行为调整」新增一行，记录目录升级、被移除的 Codex 模型、Anthropic message threads 与新路由，并链接包 README、升级指南与本日志。
- `verify-translation-pairing` 已重录 `packages/llm/llm-pi-ai/README.i18n.yaml` 与 `docs/user/guide/providers.i18n.yaml`；用户指南里指向包 README 的链接不带锚点，因为中英标题锚点不同，而配对规则要求两侧链接目标逐位一致。
