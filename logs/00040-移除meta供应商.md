# 00040 — 移除 meta 供应商

- **日期**：2026-11-18
- **背景**：`meta` 是 pi-ai 目录里的 Meta 第一方模型 API（显示名 Meta，端点 `https://api.meta.ai/v1`，`openai-responses` 协议，凭据为 `META_API_KEY` 与「Sign in with Meta」订阅 OAuth 两种），提供 6 个 Muse 对话模型：`muse-spark-1.1`、`muse-spark-1.2`、`muse-spark-1.2-contributor`、`muse-spark-1.3`、`muse-spark-1.3-contributor` 与 `muse-wonder-1.0`。六个模型均为 1,048,576 上下文、131,072 输出上限、文本与图片输入、五档可选 reasoning（`minimal` 至 `xhigh`）；目录价格分三档：Spark 1.1/1.2/1.3 为 $1.25/$4.25（缓存读 $0.15），两个 `-contributor` 条目为 $0.1/$0.2（缓存读 $0.002），`muse-wonder-1.0` 为 $4/$20（缓存读 $0.2）。
- **判断依据**：用户要求移除该供应商且不能破坏现有功能。沿用既有的 `WITHHELD_PROVIDERS` 机制：目录、模型解析、发现、登录与可配置供应商列表都不再出现该路由，不修改 `node_modules` 里的 pi-ai 包。移除代价按目录逐条核算：6 个模型中 `muse-spark-1.2-contributor` 与 `muse-spark-1.3-contributor` 也在 `opencode-go` 上以相同 id、相同能力与相同目录价格提供，其余 4 个（`muse-spark-1.1`、`muse-spark-1.2`、`muse-spark-1.3`、`muse-wonder-1.0`）没有其他内置路由，因此这是又一轮同时削减模型覆盖的移除。`openai-responses` 是可配置的自定义模型 API 协议，需要时仍可把该端点接回。移除同时减少一个 OAuth 登录流程：声明 OAuth 的已提供路由由 7 条变为 6 条（`anthropic`、`github-copilot`、`kimi-coding`、`openai`、`openai-codex`、`xai`），其中 `openai` 的 OAuth 由 `UNSERVED_OAUTH` 关闭，可用的 OAuth 流程由 6 条变为 5 条；设置页的登录按钮只出现在没有原生密钥字段的 `openai-codex` 卡片上（`meta` 有自己的 `META_API_KEY` 输入框），按钮数量不变。
- **范围**：`packages/llm/llm-pi-ai`（目录控制点与测试）、用户指南、包 README、升级指南、根 README、Web golden 与 e2e 断言、`logs/`。
- **后续变更（00043）**：`xai` 已于 [00043](00043-移除xai供应商.md) 移除。上文「声明 OAuth 的已提供路由为 6 条」中的 `xai` 不再提供，该口径变为 5 条，可用 OAuth 流程由 5 条变为 4 条；设置页登录按钮仍只出现在 `openai-codex` 上，数量不变。现行路由总数为 11 条、175 个模型，见 [00009](00009-模型供应商清理汇总.md) 顶部的「后续变更（00043）」。

## 2. 行为

- pi-ai 可对话路由 13 → **12**，目录模型 185 → **179**（只减 `meta` 的 6 个模型）；原生 DeepSeek 两条路由不变。
- `catalogProvider('meta')` 返回 `undefined`，`catalogModels('meta')` 为空；目录、模型解析、发现、登录与可配置供应商列表都不再出现该路由，设置页「添加模型提供商」由 13 项变为 12 项；登录按钮只出现在没有原生密钥字段的 `openai-codex` 上，数量不变。
- 存量 profile 点名 `meta` 时 `resolveProfiles()` 在 strict 与 deferred 下都抛 `llm-pi-ai: provider "meta" is removed from this build; delete the route or select another provider`，同一 `providers` 字典里的其他路由随之不可用，删除该条目即恢复。
- 内置 id 现为 42 = 12 个提供 + `typesafe` + 29 个被移除；`provider-data.generated.ts` 仍保留 42 个 id 的元数据（`verify-provider-data` 要求与已安装目录一致），它不是可售路由。
- 模型覆盖：`meta` 的 6 个条目中 2 个（两个 `-contributor`）仍能在 `opencode-go` 上取到同一模型，其余 **4 个失去内置入口**；需要原端点时以 `openai-responses` 自定义模型 API 接入 `https://api.meta.ai/v1`，并使用 `META_API_KEY` 或 Meta 账号授权。
- 未触及 agent loop、模型可见工具、Session 事件或持久化格式；`deepseek-official` 与 `deepseek-account` 原生路由不受影响。

## 4. 复查记录

- 覆盖口径复核（源码 probe）：6 个模型中只有两个 `-contributor` 条目在 `opencode-go` 上同 id 提供，且 api、input、cost、上下文、输出与 `thinkingLevelMap` 逐字段相同；其余 4 个在 12 条已提供路由中既无同 id（去掉厂商前缀并忽略标点）也无同显示名条目，因此「4 个失去内置路由」成立。
- 登录面口径修正：初稿把「声明 OAuth 的已提供路由」直接当成「设置页登录按钮」。`ProviderEditor` 的 `keylessNativeAuth` 只对 native auth 的 `env` 为空且声明 OAuth 的路由渲染登录（当前仅 `openai-codex`，`native-keyless` golden 亦只有它的「登录」卡片），`meta` 有自己的 `META_API_KEY` 输入框；正确结论是 OAuth 路由 7 → 6、可用 OAuth 流程 6 → 5、登录按钮数量不变。已修正本文件、00009 与 00036 的后续说明。
- reasoning 档数修正：六个模型的 `thinkingLevelMap` 只有 5 个可选级别（`minimal` 至 `xhigh`，`off` 与 `max` 为 null），本文件由「六档」改为「五档」。
- 汇总日志陈旧计数修正：00009 的 00036 后续说明标注为 00036 轮状态；目录自检、`provider-data` 行、日期与各处「28 条」计数改为 12 个路由 / 179 个模型 / 29 条。
- 用户指南协议表述修正：原句只允许「OpenAI 兼容或 `anthropic-messages`」端点，却列出使用 `openai-responses` 的 Meta 端点；改为「OpenAI 兼容对话补全、`openai-responses` 或 `anthropic-messages`」，中英成对修改并重录哈希。
- 包 README 英文措辞收紧（`through one` → `through such a route`），并重录哈希。
- `openrouter` 明细从升级指南移除后，包 README 与 00036 仍保留完整数字，来源未丢失；指南词数为 498 词。
- 升级指南的 `mistral` 段与 `meta` 段都以「第一方平台」定位，两段并列而不合并，避免把 `meta` 误写成聚合路由。
- Web golden 的既有漂移（`IM机器人` 导航按钮）来自并行的原生 IM 改动，本轮不刷新该按钮，避免把无关变更混进本次移除；provider `option` 列表本身已与目录逐项核对一致。
