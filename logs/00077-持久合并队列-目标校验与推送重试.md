# 00077 — 持久合并队列、合并后目标校验与推送重试

- **日期**：2026-11-19
- **背景**：00076 之后还剩三块：批量合并是同步调用、进程中断没有断点；合并后不再验证目标分支；通知与桌面提示的覆盖面。这轮补齐。
- **范围**：`src/app/merge-queue.ts`（新增）、`src/app/runtime.ts`、`src/app/passes.ts`、`src/app/notifications.ts`、`src/app/tools/main.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/app/views/tickets.ts`、`src/app/webhook.ts`、`src/core/model.ts`、`src/kv.ts`、`src/client/ticket.tsx`、`src/client/notify.ts`、`src/client/locales.ts`、`docs/001`–`007`、`README.md`、`NATIVE.md`、`tests/`。

## 1. 持久合并队列

- 新增 `src/app/merge-queue.ts`：队列存在 KV（`KV.runtime.mergeQueue`）里，一条记录包含 `ticketId`、`at` 和策略/清理/推送选项；提供入队、出队、取队首、查位置。存在 SQLite 里，所以重启后仍在。
- `orchestrator_merge_queue`（20 → 21 个工具）：`ticket_ids` 入队或 `cancel: true` 出队；入队前校验“已结束且未合并/未丢弃/未清理”，否则当场报错。
- pass 的 `mergeQueue` 钩子调用 `Runtime.runMergeQueue`，一次把队列排空：逐条走 `mergeTicket` 的同一套闸门，origin 记 `auto`（人登记、主机执行），每条结果用 `receiptNotice` 回主会话；失败也把该条移出队列并继续下一条；入队后再被合并/丢弃的条目记为“skipped”。
- 出队只对“还没开始”的条目生效（正在合并的那条会跑完），与 GitHub 取消队列的语义一致。
- 面板：工单页显示“已排入合并队列，第 N 位”和 **移出队列**（`POST tickets/:id/dequeue`）。

## 2. 合并后目标校验

- `mergeOnce` 在合并落库、推送之后，若配置了 `executor.check`，会在**合并记录里的仓库根**上再跑一次检查，结果记到 `Ticket.targetCheck` 并展示在工单页。
- 失败会留 `check` 通知（“合并后目标分支检查失败……这次合并可以回退”），合并本身不回滚，回退由人决定。
- 工单结束时配置检查失败也会留一条 `check` 通知（以前只有工单页上能看到）。

## 3. 推送重试与通知

- 新增 `Runtime.pushTicket` 与 `POST tickets/:id/push`：已合并且推送失败的工单可以在面板 **重试推送**，结果覆盖 `merged.push` 并写归档；成功/失败都留 `push` 通知。
- 通知类型再加 `check` 与 `push`，webhook 同步。
- 桌面通知：`src/client/notify.ts` 现在还会轮询 `GET notifications`，把 `merged`/`reverted`/`ci`/`automerge`/`check`/`push` 这些“工单状态看不出来”的事件播报出来；等待与结束仍由工单状态判定，不会重复。

## 4. 测试

- `tests/merge.spec.ts`：合并后目标检查失败仍保留合并并留 `check` 通知；队列按顺序排空、失败条目跳过且后面的继续、出队生效、被合并过的条目跳过、非法入队拒绝；`workspaceCheck` 改为 mock，避免在测试里真跑命令。
- `tests/chat-tools.spec.ts`：`orchestrator_merge_queue` 的入队参数、取消参数，以及单条合并工具不再接受列表。
- `tests/notify.spec.ts`：收件箱事件转桌面通知，等待/结束类不重复播报。
- `tests/panel-execution.spec.tsx`：队列位置与移出按钮、重试推送按钮、合并后目标检查区块。
- 模型面预算：新增工具后实测 64,337，`BUDGET.orchestrator` 由 63,500 调到 64,400。

## 6. 仍然存在的差距

- 队列是串行同步执行，一条卡在很慢的检查上会推迟后面的条目；没有“按最新目标重排/重试”的合并队列语义。
- 合并后目标检查失败只通知，不自动回退；也不会把整个仓库的提交历史回滚。
- 评审仍无“谁”、无多人批准/CODEOWNERS；diff 仍是整段字符串，没有按文件“已查看”。
