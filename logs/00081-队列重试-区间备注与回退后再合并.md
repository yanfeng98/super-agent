# 00081 — 队列失败可重试、区间备注、回退后可再合并

- **日期**：2026-11-20
- **背景**：00080 之后单人视角剩下的三处：队列失败即出队、备注只能锚一行、回退过的工单变成死路。
- **范围**：`src/app/merge-queue.ts`、`src/app/runtime.ts`、`src/app/http.ts`、`src/app/api.ts`、`src/app/tools/main.ts`、`src/app/views/tickets.ts`、`src/core/model.ts`、`src/core/tickets.ts`、`src/core/engine.ts`、`src/core/errors.ts`、`src/client/ticket.tsx`、`src/client/execution.tsx`、`src/client/locales.ts`、`docs/003`、`docs/005`、`docs/006`、`docs/007`、`README.md`、`NATIVE.md`、`tests/`。

## 1. 队列失败可重试

- 队列条目新增 `error`：失败时留在原位并记下原因，不再被移出；排空只取**第一条没有失败**的条目（`nextQueuedMerge`），所以后面的条目照常进行。
- 重试：`retryMerges` 清掉失败标记，下一次 pass 重新尝试；入口是聊天工具 `orchestrator_merge_queue` 的 `retry` 和面板条目上的 **重试**（`POST merge-queue/retry`）。
- 重新登记同一工单也会清掉失败并带上新选项（`enqueueMerges` 更新已有条目）。
- **自检抓到的真 bug**：排空改成“取第一条未失败”之后，移除仍用只删队首的 `shiftQueuedMerge`，于是“队首失败、后面成功”时队首永远删不掉，`for (;;)` 里死循环（测试进程 CPU 占满、超时都不触发）。修法：按 id 移除（`dequeueMerges`），删掉只删队首的辅助函数，并给排空加了“同一条目连续出现就停止”的保险。

## 2. 区间备注

- `TicketNote.endLine`：备注可以覆盖一段行范围；`Tickets.addNote` 校验“有结束行就必须有起始行，且结束行不早于起始行”（新错误码 `invalidNoteRange`）。
- 面板表单多一个“结束行（可选）”；列表显示 `file:12-20`；发给 worker 的备注汇总也按区间格式化。
- API 请求体增加 `endLine`。

## 3. 回退后可再合并

- `revertTicket` 成功后删除 `merged`，只保留 `reverted`（其中记着被撤销的合并提交）：工单回到“可合并”状态，修好之后能再次合并；归档同时留着合并节与回退节。
- 面板只在“回退之后没有再合并”时显示回退提示；历史行显示“被撤销的合并 → 反向提交”。
- 反复回退仍然成立：再次合并后再回退，`reverted` 记录最新一次。
