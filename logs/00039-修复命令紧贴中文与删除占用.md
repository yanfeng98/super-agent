# 00039 — 修复命令紧贴中文与删除占用

- **日期**：2026-11-17
- **背景**：用户反馈「`/goal` 那条消息没办法编辑、会话删不掉、编辑后目标也没办法取消」。排查确认是三件事叠在一起：`/goal集成进…` 因为命令名后没有分隔符而被当作普通消息；截图里的 `分析 dsh-im 项目 (1)(2)(3)` 是编辑消息分叉出来的会话；删除失败来自 Host 的 `session/in-use`，而旧流程只回一句「请稍后重试」。
- **范围**：`packages/client/ui-commands`、`packages/client/ui-workspace`（源码、八语种文案、测试）、两份包 README 与配对记录、`logs/`。未改 Host 侧命令语法与 `session/delete` 契约。

## 2. 行为

- `/goal完成目标` 回车等价于 `/goal 完成目标`，会创建目标并显示目标条；`/goal`、`/goal clear`、`/goal edit …` 不受影响。
- 命令名后紧跟 ASCII 名字字符时（如 `/goalkeeper`）仍按普通文本发送；紧贴非拉丁文字但名字未注册时（如 `/tmp文件`）同样保持普通文本，不产生「未知命令」。
- 共享命令语法（`parseCommand`）与 SDK、IM 等通道不变：分隔符仍是线上契约，宽容只发生在 Web composer 的回车认领。
- 删除主视图会话时若 Host 报 `session/in-use`，本窗口先关闭该视图并释放引用，400ms 后重试一次；仍失败时按新文案提示占用来源。另一次成功的删除仍会清空选择回到新建会话视图。
- 其他删除拒绝（有工作在进行、子智能体会话、已不存在）的语义与文案不变。

## 4. 复查记录

- `/goal集成进这个项目…` 在会话日志中只有普通 `user/message`、没有 `command/run`，确认目标从未创建；命令语法 `^\/([a-z][a-z0-9_-]*)(?=$|[\t\n\r ])` 要求分隔符，是这次「目标无法取消」的起因。
- 截图里的 `(1)(2)(3)` 是编辑用户消息时 `fork` 出的分支会话（`increaseTitle`），编辑即分叉，所以每编辑一次多一个会话；它们不是目标。
- 删除失败文案 `delete.confirm.inUse` 对应 Host 的 `session/in-use`；旧代码只把错误映射成文案，没有任何恢复动作。
- 复核时特意没有放宽 `parseCommand`：仓库已有「`/goal🔥` 不是命令」的固定用例，command 名边界属于共享契约；宽容放在 composer 认领层，避免影响 SDK 与 IM 通道。
- 首次文档校验 `package README Summaries` 因 Summary 超 100 词失败，收紧 Summary 后 21 个 gate 全绿。

## 5. 已知限制

- 「有工作在进行」（turn/job/subagent/schedule）的删除仍然只提示先停止，没有「停止并删除」按钮；需要给 `session/delete` 增加 `stopActivity` 选项并改对话框，属于 Host remote 契约变更，留待下一步。
- 重试只覆盖本窗口自身持有视图造成的占用；另一个 DSH 实例长期持有该会话时仍会失败，只能按新文案关闭该实例。
- 客户端插件是动态 bundle：已在运行的服务需要刷新页面才会加载新产物，仅重启后端不改变浏览器已缓存的 bundle。
