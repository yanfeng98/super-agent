# 00035 — 接通提供商登录入口（openai-codex 的 ChatGPT 订阅）

- **日期**：2026-11-17
- **背景**：上一轮把 `google-vertex` 从可售路由里移除后，用户问「如果我有 GPT 订阅，目前代码仓库是支持的是吗」。检查结论是**代码里有雏形、产品上没入口**：pi-ai 的 `openai-codex` 路由（9 个模型，`https://chatgpt.com/backend-api`，仅 OAuth）在售，`llm-pi-ai` 也把它的登录注册进了 `ctx.authorization`（`authorization.registerFlow`，key 为 `llm-pi-ai/openai-codex`），凭据解析与刷新都通；但全仓库只有 DeepSeek 账号自己调用过 `authorization.begin()`，客户端里 `settings.models.sign-in` 槽只有 DeepSeek 账号插件注册，模型设置页对「无原生密钥 + 有 OAuth」的提供商直接不渲染密钥字段，选中后只剩「自定义设置」和保存——保存下来的路由没有凭据，第一次请求必然失败。`openai` 那条 Sign in with ChatGPT 则被 `UNSERVED_OAUTH` 主动关掉（pi-ai 要求 app 传入稳定安装 UUID，harness 没有）。用户要求「做一次，不要破坏这个项目的正常功能」。
- **判断依据**：这条缝本身是完整的——`AuthorizationService` 有 `list/describe/begin/cancel`，`AuthorizationSession` 有 `notify/prompt/commit`，`AuthorizationInteraction` 由调用方在 `begin()` 时提供；缺的只是「浏览器怎么驱动它」。`begin()` 会一直等到整个流程结束（登录要几分钟），所以页面不能同步等它，必须后台跑 + 轮询；每个 key 同时只允许一次尝试是 seam 自己的规则，因此**用凭据 key 而不是 attempt 句柄做地址**，重新加载的页面才能接回它离开时的那次尝试。据此新增一个 `authorization` Remote namespace，并在模型设置页为「无密钥可填」的路由渲染登录入口。
- **范围**：`packages/api/settings-controller`（新 namespace 与 wire 类型、依赖声明、tsconfig 引用）、`packages/api/remotes`（客户端类型再导出）、`packages/client/ui-settings-models`（登录状态库、弹窗、卡片入口、8 种语言文案、页面 store join）、`packages/experimental/liveshare`（新 endpoint 的 viewer 分类）、`scripts/gen-cordis-catalog.ts` 与 `scripts/gen-doc-graphs.ts`（服务与类型的文档归属）、生成物（`docs/config-catalog*`、`docs/subsystems/credentials*`、`docs/capability-seams*`、`packages/extensions/tool-cordis/src/api-catalog.ts`）、Web golden、包 README 与用户指南、本日志。

## 2. 行为

- 模型设置页选中 `openai-codex`（或任何「`nativeAuth.env` 为空 + 有 OAuth」且 Host 提供登录流程的路由）时，卡片显示「登录」与流程自己的方法按钮，替代原本缺失的密钥字段；没有流程时仍然什么都不显示。
- 点击方法按钮即开始 pi-ai 的登录：codex 先问「Browser login / Device code login」，选择后按其自身逻辑发出 `auth_url` 或 `device_code` 通知，需要时再问一次代码；页面逐条显示通知、链接与验证码，回答后继续，成功后凭据由 pi-ai 通过 harness 凭据存储写入 `llm-pi-ai/<provider>` 记录，页面的 `credentials/record-updated` 推送随即刷新徽标。
- 同一 key 同时只允许一次尝试：已有时接回而不是新开；页面刷新后打开同一路由仍能看到正在进行的尝试并继续回答；关闭弹窗会撤回（幂等）；15 分钟无回答则失败并释放 key。
- 失败分两类：`authorization/*` 与 `gateway/*` 等 Host 拒绝以本地化「登录失败。」+ Host 原文显示，并给「重试」；`openai` 路由仍然只有 API key，`UNSERVED_OAUTH` 未改动。
- 未改动：seam 的 `AuthorizationService` 契约、pi-ai 目录与 `WITHHELD_PROVIDERS`、14 个可售路由与 581 个模型、凭据存储格式、Session 事件与持久化格式、agent loop 与工具 schema。`authorization` namespace 属于新增，不改变任何既有 endpoint 的签名。

## 4. 实现与首轮复查记录

1. 首版把 `AuthorizationController` 的 `seam()` 返回类型写成条件类型，编译即失败；改为直接导入 seam 的 `AuthorizationService`/`AuthorizationEntry` 类型。
2. 首版 `viewPrompt` 引用了 `PendingPrompt` 上不存在的 `prompt` 字段；把问题本身放进 `PendingPrompt` 后再投影。
3. `@Remote async` 方法只要没有 `await` 就被 `require-await` 拒绝，而给它们加空 `await` 只会掩盖问题；`list/begin/state/answer/cancel` 都不需要等待，于是改成同步方法（`settings.describe()` 同为同步远程方法的先例），并去掉测试里对这些调用的 `await`。

## 5. 复查与修复（第二轮）

复查本次改动时发现并修复了三个真实缺陷，均已补回归用例：

1. **取消发生在「启动」还在途中时，Host 上会留下无人看管的尝试。** `begin` 先把 key 写进 store、`await state()`，随后才 `begin()`；在这个窗口里点「取消」时 Host 还没有尝试可撤回，`await` 继续下来仍会创建一次没人观察的登录，占着 key 直到 15 分钟过期。修复：`cancel()` 递增代次，`begin` 的每个 `await` 之后发现代次变了就补发一次 `authorization.cancel(key)`——无论 Host 先收到哪条请求，最终都不会留下孤儿尝试。
2. **Host 不再持有该尝试时，页面会永远「等待中」并每 800ms 空转。** `state()` 返回 `null`（Host 重启，或别处已撤回）时原实现直接 `return`，界面停在运行态且轮询不停。修复：新增 `ended` 状态与 `signInEnded` 文案（8 种语言），报告「本次登录已结束」并提供重试，同时停止轮询。
3. **重复提交或问题已被替换时，一次被拒绝的回答会把仍在运行的登录显示成失败。** 第二次点「继续」会收到 `authorization/no-prompt`，原实现直接进入 failed；修复：被拒后先重读 `state`，有尝试就发布真实状态（通常是仍在运行、换了新问题），只有确实没有尝试时才报告已结束。

另外去掉了授权成功后页脚重复的「关闭」（Modal 自带一个关闭按钮），并把 `ui-settings-models` README 里「页面同时只运行一次尝试」的说法改成准确的「每个凭据 key 一次」，同时补上「Host 已不持有的尝试会报告为已结束」。复查轮复跑：`pnpm run build` 11/11、`pnpm run lint` 0/0（7308 文件）、`pnpm run test:docs` 21/21、两个受影响包 18 文件 / 533 测试通过、四包 41 文件 / 1030 测试通过；真实界面复验：打开登录弹窗显示 pi-ai 的方法提问，点「取消」后弹窗关闭、卡片回到登录按钮、无 console 错误。

## 6. 已知限制与回退

- 登录入口只覆盖「Host 提供流程」的「无密钥可填」路由。`openai` 的 ChatGPT 登录仍被 `UNSERVED_OAUTH` 关闭；带 API key 的提供商仍走密钥框（pi-ai 的 `api-key` 流程与密钥框重复，没有第二个入口）。
- 弹窗内容里由 pi-ai 提供的提问/提示文本是英文原样（属于流内容而非界面文案），本地化只覆盖周边界面文案。
- 尝试状态保存在进程内：重启 Host 会丢弃进行中的登录（凭据只需重新登一次）。
- 回退：删除 `ctx.plugin(AuthorizationController)` 与 `packages/api/settings-controller/src/authorization.ts`、移除客户端 `remote.authorization` 注入与 `sign-in.ts`/`ProviderSignIn.tsx`、还原 `ProviderEditor` 的 `keylessNativeAuth ? null` 分支与 `ModelsSection`、`store` 的 flow join、撤销 golden 三行与 8 种语言的 11 条文案，并重新运行 `gen-cordis-catalog`/`gen-config-catalog`/`gen-doc-graphs` 与 `verify-translation-pairing --write`。
