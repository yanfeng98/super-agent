# 飞书入口改由 dsh-im 接管

## 1. 目标

让 dsh-im 里已经配置好的飞书机器人成为 superagent 的飞书入口，并在 dsh-im 的机器人设置里加一个开关：

- 打开「交给 Superagent」后，这个机器人的文本消息进入 superagent 的工单流程；
- 关闭后释放消费者，机器人回到 dsh-im 的普通对话；
- superagent 不再要求单独配置 `lark-cli`、App Secret 或第二个飞书机器人。

## 2. dsh-im 侧

- Feishu bot 配置新增 `superagent` 愿望位，与原有的 `consumerMode` 分开：
  - 开关只记录“希望接管”，不会立即把机器人切到 external-consumer；
  - superagent 注册 `consumeInbound` 后，`consumerMode` 才变为 `external-consumer`；
  - 关闭时释放消费者、把 `consumerMode` 改回 `standalone`，并重启 runtime 恢复普通对话。
- `describeBot` / 机器人状态新增 `superagent` 与 `superagentActive`；面板的「通用」页新增「交给 Superagent」开关。
- `#startRuntime` 在 Host 重启后若发现 `superagent: true`、`consumerMode: external-consumer` 但没有消费者，会先以 standalone 启动，等 superagent 重新注册；避免机器人因消费者丢失而直接不可用。
- 新增 RPC `bot.superagent.set`，校验 `{botId, superagent: boolean}`。
- 新增中英文/RU 文案与开关测试。

## 3. superagent 侧

- 新增 `src/sources/feishu-im.ts`，作为 `./feishu-watch` 的新入口：
  - 通过 `ctx.dshIm` 的 `listBots` / `describeBot` / `consumeInbound` / `historyChecked` / `replyChecked` 工作；
  - 每 2 秒读取一次开关状态：`superagent` 为真且尚未激活时注册独占消费者，关闭时释放；
  - 事件映射为 `feishu` Source 的 Trigger，保留原始 message/chat/thread/root/parent 路由；
  - 回复走 `replyChecked`，线程上下文走 `historyChecked`，不再调用 `lark-cli`；worker 通过 `feishu-im/<trigger-id>/thread` 读取 dsh-im 的有限文本历史。
- 新增 `src/sources/dsh-im.ts`，声明同 Host `dshIm` 服务的类型。
- Feishu Source 的配置改为 `botId`、群、私聊、其他群和每页消息数；不再有 `cli`、`linkTimeoutMs`、`syncChat`、`bots`。
- Feishu Source 默认挂载（`cordis.patch.yml` 与 Web bundle 都移除了 `disabled: true`），但在 dsh-im 开关打开前保持 idle。
- 更新 Feishu skill 与 `prompts/cli.md`：worker 通过 `orchestrator_read thread/<key>` 读上下文，不再调用 `lark-cli`。
- 更新 README、SETUP、006/005/003/007、NATIVE 与根 README。

## 4. 行为与限制

| 场景 | 结果 |
|---|---|
| dsh-im 开关打开 | superagent 注册消费者，机器人文本消息成为 Trigger；普通 IM 会话、卡片、斜杠命令在该机器人上暂停 |
| dsh-im 开关关闭 | 消费者释放，`consumerMode` 回到 standalone，机器人恢复普通对话 |
| Host 重启 | 若开关仍开，先以 standalone 启动，superagent 重新注册后接管 |
| superagent 未运行/未启用 | 开关打开不会让机器人失去普通对话；它保持 standalone，直到消费者注册 |
| 支持的内容 | 人类文本、mention、私聊/群、线程/root/parent 路由、有限历史 |
| 不支持的内容 | 图片、机器人消息、群成员同步、旧 `lark-cli` 资源读取 |

独占模式是 dsh-im 现有契约的一部分：一个机器人同时只能有一个消费者。`consumerMode` 持久化后，释放消费者或重启 Host 不会自动回到 standalone；superagent 的 watch 会重新注册，dsh-im 的启动逻辑在没有消费者时先按 standalone 运行。

## 5. 兼容与遗留

- 旧的 `src/sources/feishu.ts`、`feishu-loops.ts`、`feishu-read.ts`、`feishu-image.ts` 仍在源码中，供旧的 `orchestrator_read feishu/...` 资源路径和旧测试使用；新的 `./feishu-watch` 不再挂载它们。
- `orchestrator_read thread/<key>` 使用新 Source 的 `threadContext`，是 worker 读取 Feishu 上下文的推荐路径。
- 旧 Feishu Source 配置里的 `cli` 等键会被新 schema 忽略，不会阻止 Source 打开；需要在面板里重新选择 dsh-im 机器人。
- 旧 `deployment.feishu` 与 setup 的 `lark-cli` 探测仍在代码中，用于旧 Source 的兼容路径；新 Source 不依赖它。
