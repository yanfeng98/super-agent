# 00043 — 移除 xai 供应商

- **日期**：2026-11-18
- **背景**：`xai` 是 pi-ai 目录里的 xAI 第一方模型 API（显示名 xAI，端点 `https://api.x.ai/v1`，`openai-responses` 协议，凭据为 `XAI_API_KEY` 与「Sign in with SuperGrok or X Premium」订阅 OAuth 两种），提供 4 个 Grok 对话模型：`grok-4.3`、`grok-4.5`、`grok-4.6` 与 `grok-4.7`。四个模型均为文本与图片输入、reasoning 能力；目录价格与容量如下：

| 模型 | 上下文 | 输出上限 | 价格 in/out（缓存读；>200k 输入阶梯 in/out、缓存读） | 可选 reasoning |
|---|---|---|---|---|
| `grok-4.3` | 1,000,000 | 30,000 | $1.25/$2.5（$0.2；$2.5/$5、$0.4） | off、low、medium、high |
| `grok-4.5` | 500,000 | 500,000 | $2/$6（$0.3；$4/$12、$0.6） | low、medium、high |
| `grok-4.6` | 500,000 | 500,000 | $2/$6（$0.5；$4/$12、$1） | low、medium、high、xhigh |
| `grok-4.7` | 500,000 | 500,000 | $2/$6（$0.5；$4/$12、$1） | low、medium、high、xhigh |

- **判断依据**：用户要求移除该供应商且不能破坏现有功能。沿用既有的 `WITHHELD_PROVIDERS` 机制：目录、模型解析、发现、登录与可配置供应商列表都不再出现该路由，不修改 `node_modules` 里的 pi-ai 包。移除代价按目录逐条核算：`grok-4.5`、`grok-4.6` 与 `grok-4.7` 也在 `github-copilot` 上以相同 id 提供（该路由的输出上限为 128,000，`grok-4.5` 的缓存读取价为 $0.5、阶梯 $1），`grok-4.7` 另在 `opencode-go` 上以相同 id、能力与目录价格提供，只有 `grok-4.3` 没有其他内置路由，因此这是一轮部分削减模型覆盖的移除（4 个模型中 1 个失去全部内置入口）。`openai-responses` 是可配置的自定义模型 API 协议，需要时仍可把该端点接回。移除同时减少一个 OAuth 登录流程：声明 OAuth 的已提供路由由 6 条变为 5 条（`anthropic`、`github-copilot`、`kimi-coding`、`openai`、`openai-codex`），其中 `openai` 的 OAuth 由 `UNSERVED_OAUTH` 关闭，可用的 OAuth 流程由 5 条变为 4 条；设置页的登录按钮只出现在没有原生密钥字段的 `openai-codex` 卡片上（`xai` 有自己的 `XAI_API_KEY` 输入框），按钮数量不变。
- **范围**：`packages/llm/llm-pi-ai`（目录控制点与测试）、用户指南、包 README、升级指南、根 README、Web golden 与 e2e 断言、`logs/`。

## 2. 行为

- pi-ai 可对话路由 12 → **11**，目录模型 179 → **175**（只减 `xai` 的 4 个模型）；原生 DeepSeek 两条路由不变。
- `catalogProvider('xai')` 返回 `undefined`，`catalogModels('xai')` 为空；目录、模型解析、发现、登录与可配置供应商列表都不再出现该路由，设置页「添加模型提供商」由 12 项变为 11 项；登录按钮只出现在没有原生密钥字段的 `openai-codex` 上，数量不变。
- 存量 profile 点名 `xai` 时 `resolveProfiles()` 在 strict 与 deferred 下都抛 `llm-pi-ai: provider "xai" is removed from this build; delete the route or select another provider`，同一 `providers` 字典里的其他路由随之不可用，删除该条目即恢复。
- 内置 id 现为 42 = 11 个提供 + `typesafe` + 30 个被移除；`provider-data.generated.ts` 仍保留 42 个 id 的元数据（`verify-provider-data` 要求与已安装目录一致），它不是可售路由。
- 模型覆盖：`xai` 的 4 个条目中 3 个仍能在其他内置路由上取到同一模型（`grok-4.5`、`grok-4.6` 在 `github-copilot`，但输出上限为 128,000、`grok-4.5` 缓存读价更高；`grok-4.7` 在 `opencode-go` 上以相同 id、能力与目录价格提供），**`grok-4.3` 失去全部内置入口**；需要原端点时以 `openai-responses` 自定义模型 API 接入 `https://api.x.ai/v1`，并使用 `XAI_API_KEY`。
- 未触及 agent loop、模型可见工具、Session 事件或持久化格式；`deepseek-official` 与 `deepseek-account` 原生路由不受影响。

## 4. 复查记录

- 覆盖口径：先按 id 精确比对，再按去掉厂商前缀并忽略标点、以及显示名比对；`grok-4.3` 无匹配，`grok-4.5`、`grok-4.6`、`grok-4.7` 都有承接路由，因此不写成「整条路由移除即失去 4 个模型」。
- 承接差异：`github-copilot` 上的三个同 id 条目并非逐字段相同——输出上限为 128,000（`xai` 为 500,000），`grok-4.5` 的缓存读取价为 $0.5、阶梯 $1（`xai` 为 $0.3、阶梯 $0.6）；文档只写「相同 id」「相同能力与目录价格」，不写「逐字段一致」：`provider`、`baseUrl`、`compat` 必然随路由不同（`opencode-go` 用 `https://opencode.ai/inference/go/v1`，`github-copilot` 用 `https://api.individual.githubcopilot.com`）。
- 登录面：`xai` 既有 `XAI_API_KEY` 也声明 OAuth，但设置页只为 native auth 的 `env` 为空且声明 OAuth 的路由渲染登录卡片；正确结论是 OAuth 路由 6 → 5、可用 OAuth 流程 5 → 4、登录按钮数量不变，已在包 README、用户指南、升级指南与两份 logs 中统一。
- 升级指南词数：加入 `xai` 后为 529 词，超过 500 词上限；通过删除已由迁移步骤覆盖的「Add each endpoint as a custom model API.」、压缩 `openrouter` 句与未覆盖条目枚举压回 499 词，事实未减。
