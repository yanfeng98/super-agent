# 00108 — `/` 菜单按技能来源分组

- **日期**：2026-11-21
- **背景**：用户看到 `dsh-rust-anything` 带 `dsh-` 前缀，问内置的 27 个工程工作流技能（取自 `mattpocock/skills`）是否也该加前缀。讨论后确认：用户真正要的是「一眼看出这个 skill 来自哪个插件」，而不是把来源写进名字。`/` 菜单组件本来就支持分组标题（`section`，`ui-commands` 在用），但技能源没有用它，`skills/list` 也没有把来源透给前端。用户选定按来源分组。
- **范围**：`skill`（新增 `upstream` 字段）、`skill-engineering`（声明上游）、`api/session-controller`（`skills/list` 透出 `source`/`upstream`）、`client/ui-skill`（分组渲染）、相关文档与测试。**技能名一个都没改。**

## 1. 变更

| 位置 | 内容 |
|---|---|
| `packages/skill/skill/src/index.ts` | `SkillSummary` 新增可选 `upstream`（文本取自哪个上游项目，例如 `mattpocock/skills`）；`toSummary` 与 `runtimeCandidate` 透传 |
| `packages/skill/skill-engineering/src/index.ts` | 每个候选带 `upstream: 'mattpocock/skills'` |
| `packages/api/session-controller/src/types.ts` | `SkillEntry` 新增 `source`（发现根）与可选 `upstream` |
| `packages/api/session-controller/src/skill-catalog.ts` | 两个字段随 `skills/list` 返回 |
| `packages/client/ui-skill/src/client/index.ts` | 候选项带 `section`；分组顺序 `builtin/upstream → project → user → custom → 其他`，组内保持搜索顺序 |
| `packages/client/ui-skill/src/client/locales.ts` | 8 种语言的四个分组词条（内置、项目、用户、自定义） |

菜单效果：

```
/  ─────────────────────────────
   mattpocock/skills
     tdd …
     grilling …
   项目技能
     dsh-code-review …
   用户技能
     …
```

## 2. 为什么不是加前缀

| | 菜单按来源分组（本方案） | 技能名加前缀 |
|---|---|---|
| 改名 | 0 | 27 个目录 + 27 处 frontmatter `name` + 正文 108 处 `/技能名` 交叉引用（7 个文件） |
| 上游镜像 | 逐字节不变 | 与 `nano-mattpocock-skills` 永久分叉，每次同步重放 |
| 上游文档 | `/tdd` 直接能用 | 得自己翻译成 `eng-tdd` |
| 第三方插件 | 装进来就自带分组 | 改不了别人的名字 |

前缀本身也不防覆盖：同名解析按层与 rank，不看名字；用户放一个同名 `dsh-tdd` 一样盖掉内置技能。

## 3. 取舍

- **分组标题用上游项目名，不用插件标题**。`工程工作流技能` 这个标题在 `locale/*.json` 里，属于插件管理的客户端元数据，宿主侧技能注册表拿不到；硬编码到宿主或客户端都会与那份翻译分叉。`mattpocock/skills` 是语言中立的专有名词，直接作为标题。
- **`source` 在 `SkillEntry` 上是 `string` 而不是 `SkillSource`**。`types.ts` 是浏览器安全的线上词汇，导入 `dsh-skill` 的类型会把宿主包拉进客户端编译面（已实测报 TS6307）。已知取值写进 JSDoc，未知来源由菜单用它自己的字符串成组。
- **不改技能名**，理由见上表。
