# 00041 — 本地工单系统（Superagent）

- **日期**：2026-11-18
- **背景**：内置的 dsh-superagent 原先只能从 GitHub Issue/PR 或飞书消息接活，部署检查还强制要求 GitHub 仓库与 agent 账号；没有这两样时整个运行时停在 setup 待配置。用户不想用 GitHub 的工单系统，需要一套本地工单：在面板里新建请求、代理照常接单执行，运行结果写回工单本身。

## 2. 行为

- 不配置 GitHub 也能启动：setup 通过，GitHub Source 显示「未配置」，本地面板可以建单、评估、派工、回复。
- 「执行 → 新建工单」填标题与请求后：请求写入 `<stateDir>/tickets/<请求 id>.md`；主 Session 评估并接单；执行器在 `Execution` 目录根下工作；代理的每条回复（已接单/结果/通知）追加到同一个 Markdown 文件，并在工单页「回复与结果」按时间倒序列出。
- 首次建单自动把 `operator` 写进 Policy；手动移除后，新建工单会被拒绝并提示去 Policy 添加。
- 工单页的「回复工单」表单把消息追加到同一 Markdown 文件，并作为 Input 送达执行器；已结束的工单会继续。写盘后在 intake 失败/filtered 时归档会回滚，重复投递按消息 id 幂等。
- 飞书、GitHub 两条既有入口不受影响；配好 GitHub 后行为与之前一致。

## 3. 复核时修掉的问题

- 本地工单问问题（attention）时，面板给出的是 `href=""` 的「回答」链接：新增工单页「回复工单」表单与 `POST local/followups`，并隐藏空链接。
- 回复重试可能重复写入 Markdown：每条消息写入 `<!-- dsh-superagent:<id> -->` 标记，重复投递只写一次。
- 标题里的换行会破坏 Markdown frontmatter：标题统一折叠为一行；标题同时进入 Trigger 文本，主 Session 可沿用。
- 20,000 字中文请求可能超过 64 KiB 请求体上限：本地工单路由改用 256 KiB。
- 无 GitHub 时 worker 仍被要求 push/PR：`prompts/work.md` 增加「账号为空时只本地提交」的条件说明。
- 新建工单成功后组件卸载仍写 state：提交顺序改为先复位再跳转。
- 追加说明指向未知/非本地线程时返回 500：路由先校验线程来源，改为 400。
- 追加说明先写归档、`receive` 失败时留下没有 Trigger 的文本：失败/filtered 时恢复归档快照。
- 同一线程的多个 Trigger 复用 `requestId` 作为消息 id，评估缓存会互相覆盖：每个 Trigger 记录自己的 `messageId`。
- 回执时间戳是入队时刻、归档是发送时刻：`settle` 时刷新回执时间，面板与归档一致。
- 只读跟随（context-only）的本地线程也会渲染「回复工单」，可能发到别的工单：只对本工单自己的本地线程显示。
- 无 GitHub 但 GitHub 来源被关闭时，worker 变量缺失会被判为「无账号」，而 git 没有提交身份：prompt 改为「没有身份时自行设置 user.name/email」。
- 首次建单前概览误报「没有允许的发送者」：概览统计各来源默认 Policy（本地工单默认 `operator`）。
- 验证补强：端到端用例覆盖「建单 → 接单 → 已接单写入文件」「Report ready → 结果写入文件」「追加说明」「幂等」，以及空 GitHub 部署与 worker 环境。
