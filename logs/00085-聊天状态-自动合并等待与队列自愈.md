# 00085 — 聊天状态、自动合并的等待与队列自愈

- **日期**：2026-11-20
- **背景**：上一轮列出的三个“需要人盯”的问题：主 session 在聊天里看不到队列和待评审；自动合并被依赖链算光 8 次尝试后自己取消；队列里的失败条目要人工 `retry` 才再试。
- **范围**：`src/app/tools/main.ts`、`src/app/runtime.ts`、`src/app/merge-queue.ts`、`src/core/tickets.ts`、`src/core/engine.ts`、`src/client/execution.tsx`、`src/client/locales.ts`、`tests/`、`docs/002`、`docs/003`、`docs/005`、`docs/006`、`docs/007`、`NATIVE.md`、`logs/`。

## 1. 聊天里能问“还剩什么”

- `orchestrator_merge_queue` 的 `ticket_ids` 改为可选；不传时只读地返回 `status`：`queue`（顺序、暂停状态、失败原因）和 `waiting`（未排队、已结束但还没合并的工单，最多 20 条，按更新时间倒序）。
- `waiting` 每项带 `needs`（`dependency` / `review` / `notes` / `merge`）、`reason`（具体的闸门说明）和 `blocked_by`（依赖的工单号）。
- 实现是 `Runtime.pendingMerges()`，闸门判断统一走 `Runtime.mergeGate()`，和自动合并共用同一份判定。
- `cancel`/`retry` 没带工单号时直接报错，避免模型误把只读查询走成写操作。
- 测试：`tests/chat-tools.spec.ts` 新增“reports the merge queue and the tickets waiting…”，暂停队列后断言队列项、`needs` 与 `reason`，并断言无工单的 `cancel` 被拒绝。

## 2. 自动合并不再被依赖链用光

- `attemptAutoMerge` 在真正合并前先看 `mergeGate`：
  - 依赖未合并、评审被要求改、等待批准、有未解决备注 → 记为一次等待，但**不计入**结束请求的 8 次尝试，60 秒后重新检查；
  - 被依赖的工单已被丢弃 → 这个闸门永远不会开，仍然计数，最终照常放弃（放弃判定在“等待”分支里也要做，否则会无限重试）；
  - 检查失败、git 报错等“需要新工作”的闸门仍然计数并递增等待（60s→15min），8 次后放弃。
- `Tickets.autoMergeBlocked(id, error, counts)` 与 `Engine` 透传新增 `counts` 参数；不计数时保留 `attempts`，`next` 取一分钟。
- 通知改为“每个不同的闸门各说一次”（比较 `last.error`），依赖合并后换成检查失败时也会再说一次，而不是只在第一次说。
- 测试：`tests/merge.spec.ts` 的依赖用例改为断言 `attempts: 0`、间隔 60 秒、依赖合并后自动合并；放弃用例改用会持续失败的自有闸门（mock 的 `mergeTicket` 拒绝），另加“被丢弃的依赖仍会放弃”的用例，避免等待分支绕过放弃判定。

## 3. 队列失败条目自愈

- `QueuedMerge.error` 增加 `code`（`dependency` / `review` / `notes` / `other`），由 `Runtime.mergeFailureCode()` 在失败后按当时的工单状态记录。
- `recoverableMerges(store)` 找出“闸门已经打开”的失败条目：依赖全部已合并、评审已批准、备注已全部解决；`runMergeQueue` 每轮先 `pruneMergeQueue` 再 `recoverMergeQueue`，清掉失败标记后按原位置重试。
- 不会循环：`other` 不自动重试；`dependency` 一旦依赖合并就不会再回到未合并；`review`/`notes` 的恢复条件是单调的，重试后若败在别的闸门，会记成新的 `code`。
- 面板在失败条目上多一行提示（`queueAutoRetry`），说明依赖合并或评审通过后会自动重试；手动 **Retry** 仍然保留。
- 测试：`tests/merge.spec.ts` 的队列失败用例改为“依赖合并后不人工 retry 也会合并”；`tests/panel-execution.spec.tsx` 的失败条目带 `code: 'dependency'` 并断言提示文案。
