# 00082 — 复核 00081：队列重试、区间备注与回退后再合并

- **日期**：2026-11-20
- **背景**：按用户要求复核 00081 的三处修复。逐行读了改动与调用路径，发现三处真问题，均已修复并补测试。
- **范围**：`src/app/merge-queue.ts`、`src/app/runtime.ts`、`src/app/http.ts`、`src/app/views/tickets.ts`、`src/core/tickets.ts`、`src/core/engine.ts`、`docs/003`、`tests/`。

## 1. 重新登记失败条目并不会清掉失败（已修）

- 问题：`enqueueMerges` 用 `{ ...queue[at], ...entry }` 更新已有条目，新条目没有 `error` 字段，展开后旧的 `error` 被保留——于是“重新登记同一工单”既不清失败，也不会被排空再次尝试，与文档和日志的说法相反。
- 修复：已有条目直接整体替换（`queue[at] = entry`），位置不变、选项更新、失败清除。
- 测试：`tests/merge.spec.ts` 新增“重新登记会清掉失败并在原位重试”。

## 2. 去掉了“已回退”保护，旧记录可被二次回退（已修）

- 问题：00081 为了让回退后可再合并，删除了 `revertTicket` 里的 `if (ticket.reverted) throw`。新记录在回退时会删掉 `merged`，所以没有影响；但**旧版本留下的 `merged` + `reverted` 记录**仍会通过检查：面板会再次显示“回退合并”，点下去会对同一个合并提交再回退一次（git 报冲突或产生空提交）。
- 修复：运行时的判断改为“`reverted.at` 晚于 `merged.at` 就是这次合并已经被回退”，拒绝；面板的 `actions.revert` 用同一条件隐藏按钮。
- 测试：`tests/merge.spec.ts` 的旧记录用例、`tests/views.spec.ts` 的按钮可见性用例。

## 3. 备注路由吞掉了结构化错误码（已修）

- 问题：`POST tickets/:id/notes` 把 `UserError` 包成 `RouteError`，`failure()` 因此只返回 `{ error: 英文消息 }`，不带 `code`；面板拿不到 `invalidNoteRange`，新加的中文文案实际是死代码（旧的 `emptyNote` 同样受影响）。
- 修复：该路由不再包装，让 `UserError` 直接走 `failure()`，返回 `{ error, code, values }`；面板按 `userError.<code>` 本地化。
- 测试：`tests/http.spec.ts` 断言备注请求带上 `endLine`，以及拒绝时返回 `code: invalidNoteRange`。

## 4. 顺带修正

- `addNote` 的三处 JSDoc（core / engine / runtime）从“文件与行”改为“文件与可选的行或区间”。
- docs/003 补一句：回退提交由仓库自己 push，页面上的 **Retry push** 属于回退时清掉的那条合并记录（避免把“回退后为什么没有重试推送按钮”当成 bug）。

## 5. 复核后确认无问题的点

- 排空循环：按 id 移除 + “同一条目连续出现即停止”的保险；失败条目留在队列、后续条目继续；暂停、重试、取消互不冲突。
- `Runtime.retryMerges` 调的是模块函数而不是自身（方法名不在词法作用域内）。
- 区间备注：结束行必须有起始行、不能倒序；面板、API、发给 worker 的汇总都带区间。
- 回退后再合并：`merged` 被清空、`reverted` 保留被撤销的提交、历史显示“合并 → 反向提交”；再次合并后可再次回退。
- 合并失败留档、具名检查、评审增量未受影响。
