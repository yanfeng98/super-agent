# 00068 — 主会话可以读工单的 diff

- **日期**：2026-11-19
- **背景**：上一轮列出的剩余问题里有“主会话读不到 diff 正文”。主会话要问“可以合并吗”，却只能看到工单卡片和报告摘要，看不到真正改了哪些代码；要看只能去面板点 View diff，和“聊天里完成整条链路”的目标不符。
- **范围**：`src/app/resources.ts`、`src/app/runtime.ts`、`tests/tools.spec.ts`、`docs/003`、`docs/007`。

## 1. 新增读取资源

`ticket/<id>/diff`：返回该工单相对其 base 的已提交 diff，就是面板 **View diff** 读的同一份数据（`Runtime.ticketDiff` → `workspaceDiff`）。分页沿用读取资源的规则，默认每页 4,000 字符；diff 超过 200,000 字符时按现有上限截断。

- 只对主会话开放（`main(read)`）：worker 读它会被拒绝，报 `This resource belongs to the main Session`，worker 本来就在自己的 worktree 里，不需要这份数据。
- 工单没有工作区、没有记录 base、目录不是 git 仓库或 git 失败时，页面返回原因文本，而不是让整次读取失败。
- 没有工作区被清理后的分支时返回错误文本；清理后读不到内容是预期行为。

## 2. 边界没有变

这是只读能力：主会话可以读出改动、据此向人描述“这次改了什么”，但**批准评审仍然只能在面板做**，合并仍然要人的明确请求。工具面没有新增工具，主会话仍是 17 个。

## 3. 文档

- `003`：Workspace review 段落补一句“主会话通过 `ticket/<id>/diff` 读同一份 diff”。
- `007`：读取资源的 Ticket 子资源列表加上 `/diff`，并说明它对应面板的 View diff。

## 4. 测试

- `tests/tools.spec.ts`：主会话能读 `ticket/<id>/diff`（测试工作区不是 git 仓库，页面给原因）；worker 读同一资源被拒绝。
- `tests/model-surface.spec.ts`：资源语法变长后仍在预算内。

## 5. 验证

- 包测试：67 个文件、**1312** 个用例全部通过（清除宿主继承的 `GIT_CONFIG_GLOBAL` 后）。
- `pnpm typecheck`：通过。
- 仓库 `test:docs`：21/21；`lint` 与 `build` 见提交流程输出；预推送 typecheck 5/5。

## 6. 范围

- 只加只读资源，不新增工具、不改权限：批准仍在面板，合并仍需人的明确请求。
- 不引入 CI；diff 只是把已有数据换个入口。
