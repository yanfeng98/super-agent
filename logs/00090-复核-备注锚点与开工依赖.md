# 00090 — 复核：备注锚点、开工依赖与合并信息

- **日期**：2026-11-20
- **背景**：复核 00089 的三项修复时发现 5 个问题：合并成功后没有启动等待开工的工单；备注重映射只对备注文件做 diff，重命名可能漏掉；面板在评审头被清掉或备注提交落后时仍把备注画在行下；开工依赖在工单已开工/已结束后仍可记录，但不会生效；被丢弃的阻塞工单只显示“尚未合并”。
- **范围**：`src/core/model.ts`、`src/app/review.ts`、`src/app/runtime.ts`、`src/app/resources.ts`、`src/app/views/tickets.ts`、`src/client/ticket.tsx`、`src/client/locales.ts`、`tests/`、`docs/003`、`docs/005`、`NATIVE.md`、`logs/`。

## 1. 合并后真正启动等待开工的工单

- `mergeOnce` 在合并记录、推送和目标检查之后调用 `startWaiting()`；上一次的改动只写了方法，调用没有落盘。
- 新增 `tests/merge.spec.ts` 用例：阻塞工单合并后，等待开工的工单排入 launch；`blockTicket` 路径的用例仍覆盖记录依赖后立即开工。

## 2. 备注重映射看完整 diff

- `remapNoteAnchors` 不再用 `-- <notes' files>` 限制 diff：路径限制可能把一次重命名显示成删除或干脆不显示，导致备注被误判为未过时、继续指向旧文件。
- 现在对 `commit..head` 做完整 `git diff --unified=0 -M`，再按文件匹配备注的 `file`/`oldPath`；重命名、删除、二进制、模式变化都按原有规则处理。git 命令统一带 `-c core.quotePath=false`，中文等非 ASCII 路径不再被转义，备注和面板的路径能对上。
- `tests/review.spec.ts` 增加重命名文件、中文文件名上的备注，断言它们标为过时。

## 3. 面板只画当前评审头下的备注

- `DiffPatch` 增加 `head`；只有 `!note.commit || note.commit === head` 且未过时的备注才画在行下。
- 评审被恢复清掉（没有当前 head）时，带旧 commit 的备注不再按旧行号画进新 diff；它们仍留在备注列表里。`noteOutdated` 也把“有 commit 但没有当前 head”视为过时，聊天和备注资源不会把旧锚点当成当前。工单进行中新建的、没有 commit 的备注照常显示。

## 4. 开工依赖只在开工前可设

- `Runtime.blockTicket` 在 `blocked && start` 时检查：工单必须仍是 open，且没有任何已开始的 Assignment；否则报 “Only an open Ticket can wait to start” / “The Ticket already started…”。
- 面板的 **Wait before starting** 复选框在工单已开始或已结束时禁用；工单开始后视图不再显示该标签。
- 只挡合并的依赖（`start: false`）不受影响，已开工/已结束的工单仍可记录。
- `tests/runtime.spec.ts` 断言已开工工单设置 start 依赖被拒绝；面板用例改为未开工的工单。

## 5. 已排队的 launch 也会重新检查开工依赖

- `DshExecutor.start` 只在入队前检查依赖；如果依赖是在 launch 入队之后、执行之前记录的，原实现会直接启动。
- 抽出 `startBlocked`，`launchQueued` 在执行前再检查一次；未合并的依赖让 Assignment 保持 pending，等阻塞工单合并后由 `startWaiting` 再启动。
- `tests/runtime.spec.ts` 新增“入队后才记录依赖”的用例。

## 6. 被丢弃的阻塞工单可见

- `blockedBy` 视图和主会话的 `blocked_by` 增加 `discarded`；面板在阻塞工单被丢弃时显示 **Discarded**，而不是 **Not merged yet**。
- 这不会自动放行依赖工单：用户仍需要清除依赖或调整计划，但至少能看到它永远不会合并。

## 7. 文档与 JSDoc

- `TicketNote.commit` 改为“备注行所锚定的提交，会随代码移动”；`mergeWorkspace` 补 `message` 参数说明。
- `docs/003`、`docs/005`：开工依赖只能在未开工的 open 工单上设置；被丢弃的阻塞工单显示 **Discarded**。
- `NATIVE.md` 第 25 条补完整 diff、面板 head 过滤和开工依赖的拒绝条件。

## 9. 仍然存在的差距

- 真正的并行堆叠（B 从 A 的未合并分支起）仍需 prepare 命令使用 `DSH_SUPERAGENT_BASE`；A 被丢弃/回退时 B 要人工处理。
- 合并目标只能是当前检出分支；队列串行；目标检查失败只暂停并通知。
- 评审没有 suggested change；已查看标记只存浏览器。
- 单人部署，没有按人分配评审人、多人批准或 CODEOWNERS。
