# 00128 — 触发页优先展示未收尾条目

- **日期**：2026-11-24
- **背景**：触发页把已完成（已合并/已推送）和未完成条目按最近活动混排，打开列表不能直接看出哪些工作还没收尾。顺带有人反馈评估页选「未完成」筛选后显示「暂无」，怀疑筛选失效。
- **结论**：触发页把线程按「是否有仍未收尾的工单」分组：未收尾的排在最前的 **未收尾** 段，其余在 **其他线程** 段；评估页的「未完成」筛选确认是筛选未做出决定的评估（超时、策略变更等），本身准确，只把中文标签明确成 **评估未完成**。

## 1. 变更

| 位置 | 变更 |
|---|---|
| `src/app/views/records.ts` | 新增 `ticketWrappedUp`（合并成功且推送成功、或已丢弃才算收尾；未合并、推送失败、被回退撤销算未收尾）与 `threadUnfinished`（线程订阅的任一工单未收尾即为未收尾）；`threadSummary` 每行输出 `unfinished` |
| `src/app/views/threads.ts` | 线程列表先按未完成优先、同组按最近活动排序，再分页 |
| `src/client/trigger.tsx` | 按 `unfinished` 把本页条目拆成 **未收尾** 与 **其他线程** 两段（含数量与说明提示），无条目时仍显示空提示；不改动线程详情页 |
| `src/client/locales.ts` | 新增分组标题与说明文案；`decisionFilter.unavailable` 中文从「未完成」改为「评估未完成」，避免与工单收尾混淆 |
| `docs/005-panel.md` | Trigger / Eval 两行说明分组语义和筛选含义 |
| 测试 | `tests/views.spec.ts` 覆盖 `ticketWrappedUp` 与 `threadUnfinished` 的判定；`tests/panel-trigger.spec.tsx` 覆盖分组顺序与普通会话不归组；`tests/panel-eval.spec.tsx` 覆盖「评估未完成」确实筛出 `unavailable` 决定；fake server 的线程行补 `unfinished` 字段 |

## 2. 原因与判断

- **以工单状态而非线程阶段判断收尾**：线程阶段（订阅中、休眠等）只说明当前有没有活，不能说明工作是否落地；收尾要看订阅的工单是否已经合并（且推送成功）或被丢弃。已合并但推送失败意味着远端还未同步，仍要留在「未收尾」。
- **回退撤销合并也回到未收尾**：与工单行、详情页对合并被回退的处理一致，避免一个已撤销的合并被误判为收尾。
- **普通会话不进任何分组**：没有订阅工单的线程没产生需要落地的工作，强行归入「其他线程」会让它看起来像已完成，违背分组定义；只把它放在没有未完成条目时的平铺列表中。
- **「评估未完成」筛选本身准确**：`unavailable` 只由评估超时、策略变更等没有得出结论的情况写入；测试数据库里没有这类记录时显示「暂无」是正确结果。把标签改明确即可，不改查询逻辑。
