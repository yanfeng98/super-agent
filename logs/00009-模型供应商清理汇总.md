# 00009 — 模型供应商清理汇总

- **日期**：2026-11-13（最后一轮 2026-11-15）
- **背景**：本仓库依次移除了十七个 pi-ai 内置供应商路由（前四条为同一批，`xiaomi-token-plan-ams`、`xiaomi-token-plan-sgp` 随后分别移除，`moonshotai` 与 `moonshotai-cn` 同批移除，`qwen-token-plan`、`qwen-token-plan-cn` 与 `qwen-token-plan-individual` 同批移除，随后移除按量计费的 `xiaomi`，再移除聚合网关 `vercel-ai-gateway`，随后移除推理路由 `huggingface`，随后移除推理云 `cerebras`，随后移除 OpenCode 的按量付费 Console 网关 `opencode`，最后移除 MiniMax 的国际站端点 `minimax`）。每项改动都有独立日志，本文件汇总最终状态、文档与升级路径，便于后续维护与恢复。
- **范围**：`packages/llm/llm-pi-ai`、`docs/user/guide/providers.md`、新增升级指南、Web golden 与 `logs/`。

## 3. 控制点

| 位置 | 作用 |
|---|---|
| `packages/llm/llm-pi-ai/src/catalog.ts` 的 `WITHHELD_PROVIDERS` / `isWithheldProvider()` | 在 `servesChat` 前过滤，目录、模型解析、发现、登录、可配置供应商列表随之生效 |
| `packages/llm/llm-pi-ai/src/config.ts` 的 `resolveProfiles()` | strict 与 deferred 下都拒绝点名被移除路由的存量 profile，错误信息指出删除该路由 |
| `provider-data.generated.ts` | 仍保留十七个路由的元数据，以满足 `verify-provider-data` 对已安装目录的完整性要求；它不是可售路由 |

## 7. 恢复方式

1. 从 `WITHHELD_PROVIDERS` 删除对应 id，并同步调整注释。
2. 更新 `catalog.spec.ts` 的 withheld 列表与 `config.spec.ts` 的参数化列表。
3. 恢复或调整受影响的目录元数据测试（`loader-composition.spec.ts`，若该路由在其中有独立断言）与 3 个 Web golden。
4. 更新包 README、用户指南与升级指南，并重新记录 i18n 哈希。
5. 运行 `vitest packages/llm/llm-pi-ai`、`test:docs`、`build:check` 与 Web e2e 验证。

## 8. 已知限制

- WebKit 浏览器未安装，两个键盘可访问性 e2e 未在 WebKit 下验证；Chromium 已覆盖 golden。
- 运行中的 `127.0.0.1:3080` 进程需要重启才会反映目录变化。
- 不修改 `node_modules/@earendil-works/pi-ai`，避免上游同步冲突与 `verify-provider-data` 漂移。
- `mimo-v2.5-pro-ultraspeed` 随 `xiaomi` 失去全部内置路由；`mimo-v2.6-pro-ultraspeed` 现在只由 `openrouter` 提供（id 为 `xiaomi/mimo-v2.6-pro-ultraspeed`）；如需按量计费直连开放平台，以自定义模型 API 接入 `https://api.xiaomimimo.com/v1`。
- `vercel-ai-gateway` 移除后，其 183 个专有模型 id 失去内置路由；118 个与 `openrouter` 同名的 id 可直接改用 `openrouter`，其余需以 `anthropic-messages` 自定义模型 API 接入 `https://ai-gateway.vercel.sh`。
- `huggingface` 移除后，13 个模型名（DeepSeek-V3 系列三个、MiniMax-M1-80k、Kimi-K2-Instruct 两个、Qwen 五个、MiMo-V2-Flash、GLM-4.6V-Flash）没有其他内置路由，需以 `openai-completions` 自定义模型 API 接入 `https://router.huggingface.co/v1`；其余 64 个在 `openrouter` 上有同名条目：29 个换了厂商前缀（不能照抄 Hub 仓库名），35 个前缀相同（4 个 id 完全一致，31 个仅大小写不同）；`google/gemma-3-4b-it` 在 `nvidia` 上同名。
- `opencode` 移除后，84 个模型里 57 个 id、14 个换前缀的同名模型在其他内置路由上仍可取到；其余 13 个中 8 个是只允许 OpenCode 客户端使用的免费档，5 个付费模型（`claude-sonnet-4`、`qwen3.5-plus`、`gemini-3-flash`、`gemini-3.1-pro`、`gpt-5-codex`）需以 `openai-completions` 自定义模型 API 接入 `https://opencode.ai/inference/v1`；同一厂商的订阅路由 `opencode-go` 仍然提供，29 个模型不受影响。
- `minimax` 移除后没有模型失去全部内置路由：三个模型（`MiniMax-M2.7`、`MiniMax-M2.7-highspeed`、`MiniMax-M3`）都仍在中文站 `minimax-cn` 上以相同 id 与相同价格提供；`MiniMax-M2.7` 另见 `openrouter`（`minimax/minimax-m2.7`）与 `together`（`MiniMaxAI/MiniMax-M2.7`），`MiniMax-M3` 另见 `fireworks`、`opencode-go`、`openrouter`、`together`，`MiniMax-M2.7-highspeed` 只存在于两条 MiniMax 路由。仍走国际站需以 `anthropic-messages` 自定义模型 API 接入 `https://api.minimax.io/anthropic`。
- `cerebras` 移除后没有模型失去全部内置路由：`gpt-oss-120b` 在 `baseten`、`groq`、`openrouter`、`together` 上以 `openai/gpt-oss-120b` 提供，`qwen-3.8-27b` 在 `groq` 与 `openrouter` 上写作 `qwen/qwen3.8-27b`（catalog 名称同为 Qwen3.8 27B，仅连字符写法不同）；仍走 Cerebras 端点需以 `openai-completions` 自定义模型 API 接入 `https://api.cerebras.ai/v1`。
- 同一模型的上下文与价格按路由不同：`qwen/qwen3.8-27b` 在 `groq` 为 131,042、$0.8–$4，在 `openrouter` 为 262,144、$0.24–$2.2；`openai/gpt-oss-120b` 在 `groq`、`openrouter` 有 $0.075 缓存读价，Cerebras 自身不计缓存。
