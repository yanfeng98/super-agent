# 00009 — 模型供应商清理汇总

- **日期**：2026-11-13
- **背景**：本仓库依次移除了五个 pi-ai 内置供应商路由（前四条为同一批，`xiaomi-token-plan-ams` 随后单独移除）。每项改动都有独立日志，本文件汇总最终状态、文档与升级路径，便于后续维护与恢复。
- **范围**：`packages/llm/llm-pi-ai`、`docs/user/guide/providers.md`、新增升级指南、Web golden 与 `logs/`。

## 1. 已移除路由

| 日志 | 路由 | 说明 |
|---|---|---|
| [00005](00005-移除amazon-bedrock供应商.md) | `amazon-bedrock` | 首次引入 `WITHHELD_PROVIDERS` 与 `resolveProfiles()` 拒绝 |
| [00006](00006-移除azure供应商.md) | `azure` | 目录、配置、测试与 Web golden 同步移除 |
| [00007](00007-移除cloudflare-ai-gateway供应商.md) | `cloudflare-ai-gateway` | 保留 `cloudflare-workers-ai`，后者的目录元数据测试随之调整 |
| [00008](00008-移除cloudflare-workers-ai供应商.md) | `cloudflare-workers-ai` | 两条 Cloudflare 路由均不再提供 |
| [00010](00010-移除xiaomi-token-plan-ams供应商.md) | `xiaomi-token-plan-ams` | 小米 MiMo Token 套餐的欧洲端点，cn/sgp 两个区域端点保留 |

## 2. 当前状态

| 项目 | 数值 |
|---|---|
| pi-ai 桥接供应商 | 36 |
| pi-ai 目录模型 | 1297 |
| 原生 DeepSeek 路由 | 2（`deepseek-official`、`deepseek-account`） |
| `WITHHELD_PROVIDERS` | `amazon-bedrock`、`azure`、`cloudflare-ai-gateway`、`cloudflare-workers-ai`、`xiaomi-token-plan-ams` |

pi-ai 共内置 42 个 id：36 个提供、`typesafe` 因只含分类模型被过滤、5 个被本构建移除。

## 3. 控制点

| 位置 | 作用 |
|---|---|
| `packages/llm/llm-pi-ai/src/catalog.ts` 的 `WITHHELD_PROVIDERS` / `isWithheldProvider()` | 在 `servesChat` 前过滤，目录、模型解析、发现、登录、可配置供应商列表随之生效 |
| `packages/llm/llm-pi-ai/src/config.ts` 的 `resolveProfiles()` | strict 与 deferred 下都拒绝点名被移除路由的存量 profile，错误信息指出删除该路由 |
| `provider-data.generated.ts` | 仍保留五个路由的元数据，以满足 `verify-provider-data` 对已安装目录的完整性要求；它不是可售路由 |

## 4. 行为

| 场景 | 结果 |
|---|---|
| 设置页「添加模型提供商」 | 只显示 36 项 |
| 目录、模型解析、发现、登录 | 均不包含被移除路由 |
| 存量配置点名被移除路由 | 插件加载失败并报 `provider "<id>" is removed from this build; delete the route or select another provider` |
| 同一 profile 的其他 pi-ai 路由 | 需删除该条目后恢复；DeepSeek 原生路由由独立插件提供，不受影响 |
| `typesafe` | 仍因无对话模型被过滤，与移除无关 |

## 7. 恢复方式

1. 从 `WITHHELD_PROVIDERS` 删除对应 id，并同步调整注释。
2. 更新 `catalog.spec.ts` 的 withheld 列表与 `config.spec.ts` 的参数化列表。
3. 恢复或调整受影响的目录元数据测试（`loader-composition.spec.ts`）与 3 个 Web golden。
4. 更新包 README、用户指南与升级指南，并重新记录 i18n 哈希。
5. 运行 `vitest packages/llm/llm-pi-ai`、`test:docs`、`build:check` 与 Web e2e 验证。

## 8. 已知限制

- WebKit 浏览器未安装，两个键盘可访问性 e2e 未在 WebKit 下验证；Chromium 已覆盖 golden。
- 运行中的 `127.0.0.1:3080` 进程需要重启才会反映目录变化。
- 不修改 `node_modules/@earendil-works/pi-ai`，避免上游同步冲突与 `verify-provider-data` 漂移。
