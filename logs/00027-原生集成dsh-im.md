# 00027 — 原生集成 dsh-im

- **日期**：2026-11-17
- **背景**：dsh-im 是社区维护的 DSH IM 机器人插件，原先需要用户单独从 npm 或插件市场安装。仓库需要把它变成 super-agent 的原生默认能力：新 clone 执行 `pnpm install && pnpm run build` 后启动 Web/Desktop 就能看到「IM bots」设置页，不再依赖外部插件安装，同时不破坏现有功能。
- **范围**：`apps/web/native/dsh-im`、`packages/bundle/web-app`、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、`scripts/build.ts`、根 `README.md`、docs 门禁的 vendored 子树例外、`logs/`。

## 2. 行为

- 新 clone 执行 `pnpm install && pnpm run build` 后，`pnpm dsh web` 的侧栏与「设置 → IM bots」自动出现，无需 `dsh plugin add`。
- Web 与 Desktop 共用 `dsh-web-app` profile；未修改用户已有 profile 的 bundle 列表。
- `/goal`、`/plan` 对当时全部渠道生效；命令输出回传到原聊天，目标持久化与自动续跑仍由 DSH 负责。
- 原生构建不发布 npm 包，因此不挂载更新 RPC，也不显示「检查更新」按钮。
- 目录首次没有 workspace 时，IM 面板仍可打开；从空首页直接点侧栏偶尔需要先激活另一个面板，这是 DSH 布局行为，不是插件报错。

## 4. 复查记录

- 首次启动时所有渠道报 `cannot get property "root" without inject`：dsh-im 4.x 使用 `ctx.root`，Cordis 4.1 的服务代理拒绝未声明 inject 的属性读取。改为 symbol 根上下文并保留 legacy 回退后，13 个渠道全部启动成功。
- 上游测试使用 Cordis 4.0.1；直接解析 workspace 的 4.1.0 会让 `fiber.await()` 挂起。测试依赖固定 npm 4.0.1，Host 仍使用 DSH 的 Cordis 实例。
- `lib/` 与 `node_modules/` 被仓库忽略；新 clone 必须执行构建（仓库原有要求），因此不提交 10 MB 级构建产物。
