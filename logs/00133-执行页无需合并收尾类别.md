# 00133 — 执行页区分「无需合并 / 已收尾」与「已完成待合并」

- **日期**：2026-11-26
- **背景**：执行页的「已结束」把 T-0031（调查类，实现已在别的工单合并）和 T-0029（临时清理，证据分支已清理）也标成「已完成待合并」，但它们没有待落地的分支。
- **原因**：`ticketMark` 把任何 `ended` 且 `outcome === 'completed'` 的工单一律标成「已完成待合并」，没有看是否真有人请求合并；触发页的 `ticketSettlement` 早已按 `autoMerge`/合并队列区分收尾与否，两套口径不一致。

## 1. 变更

| 位置 | 变更 |
|---|---|
| `src/app/views/records.ts` | 新增 `mergeRequested`，按常驻合并请求与合并队列判定是否有人要求落地；`ticketSummary` 与 `ticketFacts` 输出 `mergeRequested` 和 `settlement`，各列表行沿用同一判定 |

| `src/client/marks.ts` | `completed` 工单只在 `mergeRequested` 时标「已完成待合并」；无人请求合并时标「已完成无需合并」，悬停说明同步区分 |
| `docs/005-panel.md` | 更新执行页筛选与结束标记的说明 |
| 测试 | `views.spec.ts` 覆盖两组互斥筛选与行事实；`marks.spec.ts` 覆盖两种标记；`panel-execution.spec.tsx` 覆盖两个页签的界面呈现；fixture 补新字段 |

## 2. 判断

- 「已完成待合并」表示有人要求分支落地（登记常驻合并请求或进入合并队列）但尚未合并；只有这类工单保留该标记。
- 无人请求合并的完成工单属于已收尾，与放弃、丢弃、合并成功且推送成功一起进「无需合并 / 已收尾」，复用触发页的 `ticketSettlement` 口径。
- 「已结束」与「无需合并 / 已收尾」互斥：合并回退、推送失败、关闭后待处理、待合并请求都留在「已结束」。
